- Cormorant Garamond italic은 Shotstack 자체 호스팅 폰트 목록에 없음. Google Fonts에서 ttf 받아 public/fonts/에 두고 timeline.fonts에 등록 필요 (NotoSansKR 패턴).

## 2026-05-28 (2) — A 트랙 가격 정책 결정 (B5 빈칸 채우기)

### 배경

2026-05-21 B5 결정에서 명시된 "다음 결정 영역" 5개 항목 중 본 세션이 처리하는 영역. 본 세션 범위 = 가격 표시 정책 + 결제 기능 자체는 차후. 지금은 정책 정착 + 홈피 표시 테스트 단계이며 실제 결제 기능 구현은 본 결정 영역 밖.

### 결정

#### 1. 가격 산정 기준 = 행사 사진 가격대 이하

- B5의 잠정가(소형 2만원/중형 7만원)는 행사 사진 가격대를 상회하지 않는 선에서 소비자 수용 가능한 숫자로 산정한 값. 원가 기반 산정 아님.
- Shotstack 렌더당 원가는 실측 영역으로 보류 (실제 운영해봐야 안다는 운영자 판단). 사후 실측 후 가격 조정 가능성 잠재.

#### 2. 세그먼트 차등 없음 — 모든 행사 동일 가격

- 클립 수 플랜(무료·소형·중형·대형) 가격은 행사 유형(결혼식·졸업식·기업·동호회) 무관 동일 적용.
- 같은 50클립이면 결혼식이든 졸업식이든 동일 소형 가격.

#### 3. 커스텀 상담 트랙 신설 (별도 청구)

- 특정 행사에 특수 요구사항이 있을 경우 self-serve 플랜이 아닌 별도 상담 트랙으로 처리:
  - 결혼식 특수 옵션: 개인화된 인트로, 식 당일 QR 배너, 영상 내 특수 기능 등
  - 졸업식 학교 차원 공식 신청 (수백 명 단위 대규모 행사)
- 진입점: 현재 `/pricing` 폼이 사실상 그 역할 수행 중 ("기타 (직접 입력)" 옵션 활용 가능). 별도 견적 페이지·견적 메뉴 신설은 보류 (YAGNI).
- 동선 설계(상담→견적→수락→입금→작업)는 격상 트리거 대기. 본 결정 시점엔 "트랙 존재"만 정책으로 박음.

#### 4. PG 선택 = 토스페이먼츠 (구현은 보류)

- 결제 PG는 토스페이먼츠로 방향 결정.
- 사업자등록증 등 사전 준비가 필요해 현재 시점 구현 보류. 실제 통합은 추가 테스트 후 별도 트랙(S3-05).

#### 5. 워터마크 = 없는 방향 + 정찰 영역

- 무료 플랜의 워터마크는 가능하면 없는 쪽 선호. 단, Shotstack 자체 워터마크 옵션 / 후처리 구현 비용 / 무료 플랜 인센티브 구조 트레이드오프는 정찰 후 결정.
- 정찰 결과에 따라 (a) 워터마크 없이 다른 제약으로 무료 차별화, (b) 워터마크 유지 둘 중 결정.
- **2026-05-29 갱신**: 5번 "워터마크 없는 방향" 뒤집힘. 무료에 박음, 유료엔 제거 방향으로 확정. 2026-05-29 (3) 참조.

#### 6. A 트랙 범위 메타 결정

- 본 트랙은 가격 정책 정착 + 홈피 가격 표시 테스트 영역. 실제 결제 기능 구현 영역 아님.
- 결제 기능 구현은 추가 테스트(가격 표시 반응·리드 폼 데이터 누적) 이후 별도 트랙.
- 따라서 본 결정 시점 코드 변경 없음.

### 본 결정에 미포함 — 다음 결정 영역

- 홈피 가격 표시 UI (현재 `/pricing`은 "베타 무료" 명시 + 카드 4장만, 실제 플랜 표 노출 안 됨) — 덩어리 2, CD 토큰 복구 후 R 사이클에 묶일 영역
- 워터마크 구현 방식 (위 5번 정찰 결과로 결정)
- Shotstack 원가 실측 (실제 운영 데이터 누적 후)
- 결제 PG 토스 통합 (사업자 준비 완료 후 S3-05)

## 2026-05-28 — 가격 노출 전략: B(임시 페이지+리드폼) → A(BM 결정) 순서

- **결정**: 결제 시스템·가격 미정 상태에서 B(임시 가격 페이지 + 리드 수집 폼) 먼저 배포, A(BM 결정)는 다음 트랙으로 이월. 페이지 톤은 "행사 유형별 안내 + 베타 무료 명시" 혼합.

## 2026-05-21 — B5 가격 정책 결정 (S5 모델 채택)

### 배경

2026-05-09 D1·D2 결정 본문 = "재렌더 무제한 무료 + 사용자 안심". 본 결정 시점은 영업 개시 전 가정. 본 세션에서 운영자 두 사실 짚음:
1. 재렌더는 운영자 비용 (Shotstack 렌더당 과금)
2. AI 렌더링은 비결정성 — 재렌더가 품질 향상 보장 안 함

위 두 사실이 D1·D2 전제 자체를 흔듦. 영업 개시 흐름으로 본격 진입 전 B5 결정 필요.

### 결정

#### 1. 결제 모델 = S5 (첫 렌더 유료 + 재렌더 매번 유료)

- 무료 플랜: 진짜 테스트 용도 (워터마크 + 클립 수·길이 제한)
- 유료 플랜: 실제 행사 사용. 결제 후 진행
- 재렌더 무제한 (단, 매번 결제)

#### 2. 재렌더 의미 재정의

- 영상 품질 향상 목적 ❌
- 클립 in/out 토글 목적 ⭕ (호스트가 "민준이 클립 빼주세요" 요청 응대)
- 사용자에게 "재렌더 결과는 매번 다를 수 있음" 고지 (UI + 약관)

#### 3. 플랜 구조 (기존 UI 유지 + 서버 강제 추가)

| 플랜 | 클립 수 | 길이 허용 | 워터마크 | 다운로드 |
|---|---|---|---|---|
| 무료 | 10 | 5초·10초 | 박힘 | 허용 |
| 소형 | 50 | 5~30초 (현행) | 없음 | 허용 |
| 중형 | 200 | 5~30초 | 없음 | 허용 |
| 대형 | 5000 | 5~30초 | 없음 | 허용 |

"대형 무제한"은 실질 상한 없음 → Shotstack 비용 폭주 위험. 5000 상한 둠.

#### 4. 가격 시작점 (임의값, 추후 시장 데이터로 교체)

| 플랜 | 가격 (15초 기준) | 클립당 평균 |
|---|---|---|
| 무료 | 0원 | - |
| 소형 (50클립) | 20,000원 | 400원 |
| 중형 (200클립) | 70,000원 | 350원 |
| 대형 (5000클립 한도) | 별도 견적 | - |

길이 구간별 가격 차등: 15초 기준 위 가격, 길이별 ±20% (5초 -40%, 10초 -20%, 15초 기준, 20초 +20%, 25초 +40%, 30초 +60%)

#### 5. 재렌더 가격

- 1차 재렌더: 첫 렌더의 80% (20% 할인)
- 2차 이후: 80% 고정

#### 6. 무료 → 유료 업그레이드

- 마감 전까지 플랜 업그레이드 가능 (UI 영역. 본 결정 시점 미구현)
- 마감 후 업그레이드 불가 (렌더 시작 전제 플랜 고정)

#### 7. 완성본 보존 (D2 사양 재작성 — data-flow.md 참조)

재렌더 매번 결제 → 호스트당 N개 완성본 동시 보존. 모두 7일.

## 2026-05-14 — /share/{eventId} 페이지 재도입

- **결정**: 5/12 결정으로 카카오 공유 link를 event.videoUrl로 되돌렸으나, cdn.shotstack.io가 카카오 개발자 콘솔 미등록 도메인이라 수신자가 링크 탭 시 fallback으로 Congre 홈으로 이동하는 사고 재발. /share/{eventId} 페이지를 d74152e 시점 형태로 재도입하고 카카오 공유 URL은 `${appUrl}/share/${eventId}`.
- **이유**: 카카오 공유의 link.webUrl은 카카오 개발자 콘솔에 등록된 도메인만 사용 가능. 외부 CDN URL을 직접 넣으면 fallback 발생. 이 기술 제약은 d74152e 커밋 메시지에는 있었으나 5/12 결정문에는 누락되어 재발의 원인이 됨.
- **관련 커밋**: d74152e (2026-05-09, 최초 도입), 09a6d9a (2026-05-12, 제거), 이번 커밋 (재도입).

## 2026-05-12 — 초대장 기능 제거

- **결정**: 이벤트 대시보드의 초대장 작성 섹션(환영 문구, 대표 사진, 갤러리) 및 `/invite`, `/share` 페이지 전체 제거. 카카오 공유 링크는 `/share/{eventId}` 대신 완성 영상 URL(`event.videoUrl`)로 직접 연결.
- **이유**: 초대장은 게스트 경험 개선 기능으로 기획됐으나 실제 사용률이 없고 코드 복잡도만 증가. 게스트 접근 경로는 QR 코드(업로드 토큰 URL) 하나로 충분. 완성 영상 공유는 영상 직링크가 더 직관적.
- **대안**: 초대장 유지 후 UX 개선 — YAGNI, 현재 요구사항 없음 → 기각.

## 2026-05-09 — 공유 채널 정리: 카카오 유지, 인스타 제거

- **결정**: 완성 화면의 인스타그램 공유 버튼 제거. 카카오톡 공유 버튼은 유지 (정찰에서 SDK 통합·환경변수·도메인 화이트리스트 모두 등록 확인).
- **이유**: 인스타그램은 외부 앱에서의 직접 공유 API를 일반 공개하지 않음. 현재 코드는 `instagram.com` 홈을 새 탭에서 여는 무의미한 동작. 사용자가 인스타에 올리려면 어차피 영상 다운로드 후 인스타 앱에서 직접 업로드 — 다운로드 + 링크복사 버튼만으로 충분.
- **대안**: "다운로드 후 인스타 앱에서 업로드" 안내 모달로 변경 — YAGNI, 사용자 학습 비용만 추가 → 기각.

## 2026-05-09 — 시장 정의 보강: 단체사진 영상 버전, 자동 편집 필수, 제작자 무관

- **결정**: congre는 "단체사진으로 남는 모든 행사의 영상 버전"이다. 결혼식·졸업식·사내행사·MT 등 행사장에서 축하 인사·소감·현장 분위기를 누군가가 담아 주최자에게 보내고, 주최자가 감사 인사·마무리 멘트를 더해 실시간 완성본을 받아 참가자·SNS로 공유하는 도구.
- **이유**:
  - 1순위 시장(학교 졸업식, DECISIONS 2026-05-06)의 "1인칭 자기 회고" 패턴은 시장 안에서의 활용 형태이지 서비스의 본질이 아님. 결혼식 하객 축하·사내행사 동료 코멘트 등은 타인 시점이 자연스러움.
  - 자동 편집은 비용 우위가 아니라 현장성 보존을 위한 필수 조건. 사람 편집자(WeddingMix류)는 이 가치와 양립 불가.
  - 제작자 = 폰 가진 누구나 (행사 주최자, 학생, 사원 등). UI는 특정 역할 가정 없이 흘러야 함.
  - 영상 가치 강화 방향(DECISIONS 2026-05-05의 6항목) 중 인물 보정·배경 정리는 "실제 얼굴 + 현장성" 가치와 충돌. 강화 방향은 행사 컨텍스트 표시(가상 포토월, 행사 타이틀) 쪽으로 좁힘.
- **대안**: 1인칭 회고 전용 도구로 좁히기 — 결혼식·사내행사 시장 진입 차단으로 기각.

## 2026-05-07 — 서비스 모델 정의: 비공식 기념품, 즉시 삭제 데이터 흐름

- **결정**: congre는 학교·기업 등 주최 측이 공식적으로 발주하는 행사 솔루션이 아니라, 참가자들끼리 사적으로 기념하는 도구로 정의한다. 데이터는 인터넷 망에 영구 보존하지 않고 단기 처리 후 삭제한다.
- **데이터 흐름**:
  - 개별 클립: 완성 영상 렌더링 직후 즉시 삭제
  - 완성 영상: 주최자에게만 전송 → 주최자가 참가자에게 공유 (공유 인프라는 congre가 제공) → 며칠 후 삭제
  - 주최자 공유 이후의 배포 책임은 congre 영역 밖
- **함의 — 보안·법무 판단의 공통 전제**:
  - 학교·기관 등 외부 주체의 신뢰 손상은 위협 모델에서 큰 가중치를 갖지 않는다 (학교가 발주처가 아님).
  - "인터넷 노출", "장기 보존 위험" 시나리오는 데이터 흐름상 발생하지 않는다.
  - 1순위 시장(학교 졸업식)이 미성년자 영상이라는 사실은 유효하지만, 데이터가 단기 삭제되고 친구 그룹 내부에서만 공유된다는 점이 보안·법적 위험 평가의 보정 변수가 된다.
  - 보안 작업 우선순위는 "유출"보다 "기능 신뢰성"(렌더 성공률, 알림 도달성) 쪽에 비중을 둔다.
- **적용**:
  - 향후 모든 보안·법무·기능 결정은 이 데이터 흐름을 전제로 평가한다.
  - 이 정의가 바뀌면(예: 영상 영구 보존 옵션 도입, 학교 공식 발주 진입) 본 항목을 업데이트하고 보안 우선순위를 재평가한다.

## 2026-05-06 — 1순위 시장 정의: 학교 졸업식 / 1인칭 짧은 인터뷰

- **결정**: congre의 1순위 시장은 초·중·고 졸업식. 핵심 사용 패턴은 "학생 본인이 폰으로 자기 졸업 소감을 짧게 찍은 클립을 30~100명분 모아 자동 편집".
- **시장 선정 이유**:
  - 폰 소지자 = 학생 본인 → 1인칭 자기 표현 영상 (외부 관찰자가 찍는 결혼식·어린이집과 본질 다름)
  - 현장성 강함 (당일 흥분 상태에서 즉석 인터뷰)
  - 반복 구매 (매년 졸업식)
  - 가격 저항 낮음 (인당 천원 수준, 졸업앨범 5만원 대비. 분식 1번 값으로 학생 본인이 "내 졸업 영상에 내가 들어간다" 가치를 사는 데 결정 부담 거의 없음)
  - 결제 단위 명확 (반 단위 일괄 또는 졸업앨범 끼워서)
- **포지셔닝**: "여러 명이 같은 사건을 자기 입으로 회고한 영상의 집합체". WeddingMix·Vloggi(행사 다큐멘터리)와 다르고, TikTok·릴스(개인 콘텐츠)와도 다른 자리.
- **확장 시장**: 결혼식, 기업 행사, 동창회 등은 보조 시장. 학교 졸업식에서 검증한 기술의 확장 대상.
- **함의**: 미성년자 영상이라 보안·법적 리스크 우선순위 격상. 학부모·교사 사용자 비율 높아 네이버 메일 도달성 격상. (관련 작업은 ROADMAP 참조.)

## 2026-05-05 — 영상 가치 및 강화 방향 정의 (시장 2 안에서)

- **결정**: congre의 영상 가치는 "현장성 + 실제 얼굴이 나오는 것". AI 영상 생성(시장 1, Sora·Runway 등)으로는 가지 않음.
- **강화 방향 6항목**:
  1. 인물 보정 (촬영자 예쁘게)
  2. 배경 정리
  3. 화면 특수효과
  4. 클립 인아웃 효과 (지루하지 않게)
  5. 완성 영상에 코멘트 자막 (사전 입력받은 톤앤매너 기반, 즉석 사회자 스타일)
  6. 인트로/아웃트로 (행사 주최자 입력)
- **컨텍스트**: 트랙 B 편집 엔진 리서치에서 "AI 영상 생성"과 "프로그래밍 가능한 영상 편집"이 다른 시장임을 확인. congre는 후자(시장 2)에 속함.
- **활용**: 이 6항목은 향후 편집 엔진 평가의 체크리스트. 현재 Shotstack에서 어디까지 되는지, 안 되는 게 있으면 어떤 플랫폼이 가능한지가 평가 기준.
