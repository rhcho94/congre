## 2026-08-11 — 회사 도메인 전환 + 약관 제정 처리 결정 4건

- **결정 1: 약관·처리방침을 개정이 아닌 제정으로 처리**
  - 상태: 첫 시행일 2026-09-01 확정, 부칙 v0.1·v0.2 이력 삭제 (bfc7878)
  - 이유: 약관 제3조 ③은 회원에게 불리한 변경 시 30일 전 공지를 요구하나, 회원 0명 상태의 첫 시행은 그 대상이 아니다. docs/legal/CHANGELOG.md 헤더 규약이 "시행 전 초안은 0.x, 첫 시행 = 1.0"으로 정하고 있어 v0.1·v0.2를 시행본으로 기재한 부칙 자체가 규약 위반이었다.
  - 함의: 유료 개시 전 계정·데이터 전수 초기화가 전제 조건이다. 초기화 완료 기록(날짜·건수)이 "회원 0명 시행"의 근거가 된다. 초기화 전에 실회원이 생기면 이 처리는 성립하지 않는다.

- **결정 2: 이메일 배분 — 법정 표시는 실명 계정, 고객 창구는 역할 계정**
  - 상태: 앱 하단 문의처 2곳·메일 본문 3곳 = cs@rayne.co.kr, 개인정보 보호책임자·사업자 정보 = ray@rayne.co.kr (b28f30d, f7561f6)
  - 이유: 개인정보 보호책임자와 사업자 정보 이메일은 법정 표시 성격이라 실재하는 책임자를 특정해야 한다. 고객 문의는 담당자가 바뀌어도 주소가 유지되어야 하므로 역할 계정.
  - 함의: privacy 한 페이지에 ray@ 2건 + cs@ 1건이 동시에 보인다. 의도된 배분이며 임의 통일 금지. 랜딩 푸터도 같은 구조(하단 바 cs@ + 사업자 정보 ray@).

- **결정 3: 사업자 정보 블록 신설 — 조 번호 미부여**
  - 상태: terms·privacy 두 파일에 7항목 동일 배치, 부칙 바로 앞 (f7561f6)
  - 이유: 조문이 아니라 표시 의무 이행을 위한 정보 블록이다. 조 번호를 주면 이후 조문 추가 시 번호 체계가 흔들린다.
  - 함의: 랜딩 푸터와 문자 단위로 일치해야 한다. 불일치는 카드사 심사 지적 대상. 값 변경 시 앱 2곳 + 랜딩 1곳을 항상 함께 고친다.

- **결정 4: 회사 도메인과 제품 도메인 분리**
  - 상태: 사람이 주고받는 메일은 rayne.co.kr(Google Workspace), 기계가 보내는 메일은 congre.kr(Resend·SOLAPI). 발신 도메인 무변경
  - 이유: congre.kr은 SPF·DKIM이 이미 검증된 발송 전용 도메인이라 여기에 수신 MX를 얹으면 기존 발신 설정을 건드리게 된다(2026-07-03 도메인 사고 계열). 회사 메일을 별도 도메인에 두면 앱이 늘어도 메일 인프라는 하나로 유지된다.
  - 함의: rayne.co.kr DKIM은 1024비트다 — 가비아 TXT 250자 제한 때문에 2048비트(400자)를 넣을 수 없다. 별칭 4개(cs·admin·billing·marketing)는 Workspace 요금 1인분으로 유지된다.

## 2026-05-20 — 회원 탈퇴 정책 결정 2건 (v0.2)

- **결정 1: 진행 중 이벤트 보유 시 탈퇴 차단**
  - 상태가 "open", "closed", "rendering"인 이벤트가 1개라도 있으면 회원 탈퇴 불가.
  - 이유: 유료 이벤트의 경우 환불 처리 등 복잡한 사고 발생 가능. 사용자가 모든 이벤트를 마감(완료 상태로 전환)한 후 탈퇴.
  - 함의: 마이페이지 UI에서 진행 중 이벤트 카운트 표시 + 탈퇴 버튼 비활성. 서버 API에서 재검증.

- **결정 2: 탈퇴 시 호스트 자산 일괄 삭제**
  - 탈퇴 처리 즉시 회원 계정 정보 + 모든 이벤트 문서 + 클립 (Firestore + S3) + 완성본 (Shotstack) 일괄 삭제.
  - 이유: 처리방침 제3조 "탈퇴 시까지" 보유 기간 정합. 자연 만료(cron) 대기 시 처리방침 위반 가능성.
  - 함의: 약관 제18조에 일괄 삭제 명시. 탈퇴 UI에 경고 문구 + confirm 다이얼로그 + 복구 불가 안내.

## 2026-05-10 — 약관·처리방침 v0.1 초안 결정 5건

- **결정 1: 호스트 가입 가능 연령 만 14세 이상**
  - 「개인정보 보호법」상 자기정보 동의 가능 연령 기준. 만 14세 미만은 호스트로 가입 불가, 참가자로만 이용 가능.
  - 함의: 14~18세 미성년 호스트 가능. 「민법」상 미성년자 계약 취소권은 약관 본문에 반영하지 않고 별도 의제(YAGNI). 유료 전환 시 재고.

- **결정 2: 호스트 약관 동의 흐름 D — 푸터 링크만, 명시 동의 안 받음**
  - 옵션 A(회원가입 폼 체크박스), B(이벤트 생성 시), C(첫 로그인 모달) 검토 후 D 채택.
  - 이유: 현재 회원가입 페이지 자체가 없음 (콘솔 수동 가입). 무료 베타 + 1인 운영 단계에서 「약관규제법」 제3조 명시·교부 의무는 게시로 충족. 명시적 동의 의무는 약함.
  - 함의: 가입 모델 전환 또는 유료 전환 시 동의 흐름 재설계.

- **결정 3: 만 14세 미만 참가자 정책 — 호스트 파악·안내 의무 수준**
  - 약관 제13조 ②에 "법정대리인 동의 강제"가 아니라 "파악 및 안내 의무" 수준으로 약화. ③의 "동의 확보" 표현도 "안내" 수준으로 정렬.
  - 이유: 현재 코드에 법정대리인 동의 UX 없음. 약관 강도와 실제 운영 가능성 정합.
  - 함의: 졸업식 시장 본격 진입 시 동의 UX 구현 별도 의제.

- **결정 4: 클립 저작권 — 참가자 귀속, 마케팅·홍보 사용 안 함**
  - 약관 제12조 ③: 클립 저작재산권은 참가자 본인. 회사는 서비스 제공 목적 범위 내에서만 처리·결합·삭제 권리.
  - 함의: 향후 사례 영상·마케팅에 클립 활용 불가. 활용 필요 시 약관 개정 + 별도 동의 절차 필요.

- **결정 5: 약관 베이스 — 한국 일반 인터넷 서비스 약관 표준 골격**
  - 운영자 결정 "방통위 표준약관 + 간소화"의 정확한 해석. 한국에 "방통위 표준약관"이라는 단일 문서는 없으며, 일반 서비스 약관은 공정위 표준약관 일부 + 한국 SaaS·콘텐츠 서비스 관행 결을 따라 작성됨.
  - 함의: 약관 변경 시 같은 결 유지. 공정위 표준약관(전자상거래용)이나 디지털콘텐츠 중개 표준약관을 기계적으로 차용하지 않음.

## 2026-05-09 — 약관·개인정보 처리방침 페이지 신설 (골격 분리, 콘텐츠 별도)

- **결정**: `/privacy`(개인정보 처리방침)·`/terms`(이용약관) 라우트를 페이지 골격만 코드로 신설. 콘텐츠(각 조항 본문)는 운영자가 별도로 채움. 임시 배너 표시.
- **이유**:
  - 전번 수집 코드(PR 1) 배포 전에 개인정보 처리방침 URL이 먼저 존재해야 법적 위반 방지 (개인정보보호법 제15조 — 수집 전 이용자 고지 의무).
  - 콘텐츠 작성(법무 영역)과 코드 배포를 분리해 서로 블로킹하지 않도록 함.
  - 랜딩 푸터에 링크 노출로 페이지 접근 경로 확보.
- **콘텐츠 채움 시점**: PR 1(전번 수집 코드) 배포 전에 운영자가 직접 각 항목 본문 작성 필요. 임시 배너를 제거하고 실제 내용으로 교체.
- **대안**: 콘텐츠 작성 완료 후 한 번에 배포 — 전번 수집 코드 배포가 콘텐츠 완성에 블로킹됨 → 기각.
