## 2026-08-14 — 환불 구간 이관 결정 3건

- **결정 1: 환불 경계 계산 주체를 렌더 시작 → 결제 완료로 이관**
  - 상태: 2026-08-14 `6e18ddd`. `payment/confirm`이 `paidAt` 상수를 뽑아 `refund50At`(+4시간)·`refund100At`(+48시간)을 events 문서에 기록한다. `render/start`의 계산 2줄과 NotifiedAt 리셋 2줄은 제거했다.
  - 이유: 후보 3안을 비교했다. (가) confirm에서 계산 (나) `paidAt`을 events에 복사 후 `render/start`에서 계산 (다) 기존 `closedAt` 재활용. 나·다는 재렌더 시 `render/start`가 다시 실행되면서 이미 지난 시각으로 두 필드를 재계산해, 호스트가 자기 의사로 재렌더한 건에 환불 확정 메일이 나가는 경로를 만든다. 약관 제10조의3 ③은 "회사의 사유로 지연된 경우"에만 적용되므로 이 발송은 약관 위반이다. 가는 결제가 이벤트당 1회이고 재렌더가 confirm을 거치지 않아 이 경로가 원천적으로 없다. 다는 필드 추가가 0이라 매력적이었으나, 약관이 "결제 완료 시각"을 명시하는데 코드는 마감 시각을 읽어 문서-코드 드리프트가 남는다.
  - 함의: 결제 파일에 환불 시각 계산이 들어가 관심사가 일부 섞인다. confirm이 이미 `closedAt`·`unlocked`·`status`를 쓰는 "결제 완료 시점에 확정되는 값" 자리라 수용했다. 환불 구간 값을 바꾸려면 이제 confirm 한 곳만 고치면 된다.

- **결정 2: 무료 이벤트 환불 제외를 가드 코드 없이 처리**
  - 상태: 무료 이벤트 제외를 위한 `plan` 검사 코드를 추가하지 않았다.
  - 이유: 무료 이벤트는 `payment/confirm`을 거치지 않으므로 두 필드가 기록되지 않는다. cron 조건식 `data.refund50At?.toMillis() <= now`는 필드 부재 시 옵셔널 체이닝으로 `undefined`가 되고, `undefined <= now`는 NaN 비교라 항상 거짓이다. 조건이 자연히 막힌다. `plan !== "paid"` 가드를 따로 두면 같은 규칙이 두 곳에 생겨, 나중에 한쪽만 고치는 드리프트 원인이 된다.
  - 함의: 이 성립은 "무료는 confirm을 안 거친다"는 전제에 의존한다. 무료 이벤트가 결제 경로를 지나게 되는 변경(예: 0원 결제 도입)이 생기면 이 전제가 깨진다. 그때는 명시적 가드가 필요하다.

- **결정 3: 환불 실행은 운영자 수동 처리 전제 — PG 취소 호출 미구현**
  - 상태: PG 취소 호출 코드가 저장소에 없다. 알림 메일만 자동 발송되고 실제 환불은 운영자가 토스 관리자 화면에서 처리한다. `src/emails/refund-50.ts:29`가 "환불은 저희 팀이 직접 처리하며"로 고객에게 이를 고지하고 있다.
  - 이유: 약관 제10조의3 ⑧은 "영업일 기준 3일 이내 처리"만 약속하고 자동화를 약속하지 않는다. 수동 처리로도 약관이 성립한다. 실고객 0 단계에서 취소 API 연동은 검증할 데이터가 없는 상태의 선구현이다.
  - 함의: 환불 건수가 늘면 누락 위험이 생긴다. 유료 실사용 개시 후 환불이 실제로 발생하기 시작하면 재평가 대상이다.

  - 탈퇴 처리 즉시 회원 계정 정보 + 모든 이벤트 문서 + 클립 (Firestore + S3) + 완성본 (Shotstack) 일괄 삭제.
  - 이유: 처리방침 제3조 "탈퇴 시까지" 보유 기간 정합. 자연 만료(cron) 대기 시 처리방침 위반 가능성.
  - 함의: 약관 제18조에 일괄 삭제 명시. 탈퇴 UI에 경고 문구 + confirm 다이얼로그 + 복구 불가 안내.

## 2026-05-10 — 약관·처리방침 v0.1 초안 결정 5건

- **결정 1: 호스트 가입 가능 연령 만 14세 이상**
  - 「개인정보 보호법」상 자기정보 동의 가능 연령 기준. 만 14세 미만은 호스트로 가입 불가, 참가자로만 이용 가능.
  - 함의: 14~18세 미성년 호스트 가능. 「민법」상 미성년자 계약 취소권은 약관 본문에 반영하지 않고 별도 의제(YAGNI). 유료 전환 시 재고.

- **결정 2: 호스트 약관 동의 흐름 D — 푸터 링크만, 명시 동의 안 받음**
  - 옵션 A(회원가입 폼 체크박스), B(이벤트 생성 시), C(첫 로그인 모달) 검토 후 D 채택.
  - 이유: 현재 회원가입 페이지 자체가 없음 (콘솔 수동 가입). 무료 베타 + 1인 운영 단계에서 「약관규제법」 제3조 명시·교부 의무는 게시로 충족. 명시적 동의 의무는 약함.
  - 함의: 가입 모델 전환 또는 유료 전환 시 동의 흐름 재설계.

- **결정 3: 만 14세 미만 참가자 정책 — 호스트 파악·안내 의무 수준**
  - 약관 제13조 ②에 "법정대리인 동의 강제"가 아니라 "파악 및 안내 의무" 수준으로 약화. ③의 "동의 확보" 표현도 "안내" 수준으로 정렬.
  - 이유: 현재 코드에 법정대리인 동의 UX 없음. 약관 강도와 실제 운영 가능성 정합.
  - 함의: 졸업식 시장 본격 진입 시 동의 UX 구현 별도 의제.

- **결정 4: 클립 저작권 — 참가자 귀속, 마케팅·홍보 사용 안 함**
  - 약관 제12조 ③: 클립 저작재산권은 참가자 본인. 회사는 서비스 제공 목적 범위 내에서만 처리·결합·삭제 권리.
  - 함의: 향후 사례 영상·마케팅에 클립 활용 불가. 활용 필요 시 약관 개정 + 별도 동의 절차 필요.

- **결정 5: 약관 베이스 — 한국 일반 인터넷 서비스 약관 표준 골격**
  - 운영자 결정 "방통위 표준약관 + 간소화"의 정확한 해석. 한국에 "방통위 표준약관"이라는 단일 문서는 없으며, 일반 서비스 약관은 공정위 표준약관 일부 + 한국 SaaS·콘텐츠 서비스 관행 결을 따라 작성됨.
  - 함의: 약관 변경 시 같은 결 유지. 공정위 표준약관(전자상거래용)이나 디지털콘텐츠 중개 표준약관을 기계적으로 차용하지 않음.

## 2026-05-09 — 약관·개인정보 처리방침 페이지 신설 (골격 분리, 콘텐츠 별도)

- **결정**: `/privacy`(개인정보 처리방침)·`/terms`(이용약관) 라우트를 페이지 골격만 코드로 신설. 콘텐츠(각 조항 본문)는 운영자가 별도로 채움. 임시 배너 표시.
- **이유**:
  - 전번 수집 코드(PR 1) 배포 전에 개인정보 처리방침 URL이 먼저 존재해야 법적 위반 방지 (개인정보보호법 제15조 — 수집 전 이용자 고지 의무).
  - 콘텐츠 작성(법무 영역)과 코드 배포를 분리해 서로 블로킹하지 않도록 함.
  - 랜딩 푸터에 링크 노출로 페이지 접근 경로 확보.
- **콘텐츠 채움 시점**: PR 1(전번 수집 코드) 배포 전에 운영자가 직접 각 항목 본문 작성 필요. 임시 배너를 제거하고 실제 내용으로 교체.
- **대안**: 콘텐츠 작성 완료 후 한 번에 배포 — 전번 수집 코드 배포가 콘텐츠 완성에 블로킹됨 → 기각.
