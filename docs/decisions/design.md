# Decisions — design (룩앤필·디자인 토큰·로고·화면 규칙)

> 앱(app.congre.kr)과 랜딩(congre.kr) 공통 디자인 결정. 새 결정은 맨 위에 추가.

## 2026-10-08 — 한국어 줄바꿈은 단어 단위, 가운뎃점 나열 마저 정리

- **결정**: 앱 본문 줄바꿈을 단어(띄어쓰기) 단위로 한다(`body`에 `word-break: keep-all`, 띄어쓰기 없는 긴 글자가 칸을 넘지 않게 `overflow-wrap: anywhere`). 랜딩 site.css는 이미 keep-all이다. F 규칙의 가운뎃점 나열이 남아 있던 4곳(이벤트 화면 미디어 안내 2곳, 촬영 화면 안내, 초대 링크 미리보기 제목)을 고치고, 미리보기 제목은 탭 제목과 같은 " | "로 잇는다("{호스트}님이 초대했어요 | {행사명}"). 랜딩 자주 묻는 질문의 질문 줄은 누르는 높이 44px로 한다.
- **근거**: 2026-10-08 로컬 화면 점검에서 "삭제됐어 / 요"처럼 한 글자만 다음 줄로 떨어지는 줄바꿈, 남은 가운뎃점 4곳, 44px보다 낮은 FAQ 질문 줄(32px)을 찾았고 Ray가 모두 고치기로 했다. 가운뎃점이 남은 까닭은 사양서의 점검 검색 목록에 " · "가 빠져 있었기 때문이다.
- **출처**: 2026-10-08 채팅(로컬 점검 결과 보고).

## 2026-10-07 — 앱 화면의 결혼식 단어를 일반 단어로

- **결정**: 시안(결혼식안)의 호스트·참가자 화면 문구를 쓰되, 결혼식에만 맞는 단어는 일반 단어로 바꾼다. 식장 → 행사장, 예식 → 행사, 청첩장 → 초대장. "하객", "축하", "축의대"는 그대로. 랜딩은 결혼식 문구 그대로.
- **근거**: 앱에는 행사 종류 필드가 없어 돌잔치·생일·칠순 호스트도 같은 문구를 본다(Q3 (b)안, Ray 승인).
- **예**: 호스트 화면 "행사장 입구나 축의대 옆에 QR을 세워 두세요. 모바일 초대장에 링크를 넣어도 돼요.", "행사가 끝나면 마감해 주세요."
- **출처**: 2026-10-07 채팅 Q3.

## 2026-10-07 — 다크 테마 폐지, 참가자·공유 화면 사진 배경 교체

- **결정**: 업로드(참가자)·공유 화면의 다크 테마(`[data-theme="dark"]`)를 없애고 다른 화면과 같은 밝은 종이 톤으로 바꾼다. 사진 배경은 유지하되 그림을 행사 공용 사진으로 바꾼다: `public/images/bg-event.jpg`(파티 조명·풍선 사진, 원본 Kling `kling_20260525_作品_Vertical_9_4403_0.png`). 사진 위에 종이색을 덮었고 아래로 갈수록 바탕색으로 완전히 덮이게 그림 파일에 미리 입혔다(CSS 그라디언트 아님). 사진은 페이지 맨 위에만 보이고 함께 스크롤된다. 옛 배경 bg-stage-a~e.png(합계 약 27MB, a~d는 미사용)는 삭제했다.
- **근거**: Ray 결정 2 "사진 배경 유지" + 화면 점검 E9(생일파티 아이들 사진이 결혼식·돌잔치 등 모든 행사 화면에 나오는 문제). 행사 종류와 상관없는 사진으로 바꾸면 사진의 따뜻함은 남고 E9는 풀린다. 글자를 읽기 쉽도록 사진은 위쪽에만 보이게 했다. 다크 테마는 밝은 롤링페이퍼안과 어울리지 않고, 다크 스코프 색 상속 문제(known-issues "게스트 화면 data-theme 미적용")도 함께 사라진다.
- **출처**: 2026-10-07 채팅 결정 2(사진 배경 유지)와 그 뜻을 정한 추가 질문(행사 공용 사진으로 교체하는 안).

## 2026-10-07 — 참가자 첫 화면 흐름 유지

- **결정**: 참가자 첫 화면은 시안 디자인을 따르되 흐름은 바꾸지 않는다. 이름·전화번호 → "다음" → 촬영 화면. 시안처럼 첫 화면에 "10초 영상 찍기" 버튼을 두지 않는다. 대신 개인정보처리방침 링크 + 동의 체크(A1)와 참가자 가이드 링크(D12)를 넣었다. 동의 체크는 화면에서만 확인하고 저장하지 않는다.
- **근거**: 흐름 변경은 E·F(디자인 정리) 범위 밖이다. 두 단계를 합치면 아이폰에서 "지금 촬영하기"를 숨기는 분기까지 다시 짜야 한다(Q4 (a)안, Ray 승인). 동의 기록 저장은 법률 상담 뒤 필요하면 별도로 한다.
- **출처**: 2026-10-07 채팅 Q4, 시트 A1·D12.

## 2026-10-06 — 로고 D "영상 쪽지"

- **결정**: 로고를 D "영상 쪽지" 하나로 통일한다. 모양(viewBox 0 0 100 100): 쪽지 `M18 22h52l12 12v44H18z`(흰 채움, 잉크 선) · 접힌 모서리 `M70 22v12h12` · 재생 삼각형 `M43 33l18 11-18 11z`(잉크) · 빨간 펜 물결 `M30 66c4-3 8-3 12 0s8 3 12 0 8-3 12 0`(#C62828, 굵기 3.5) + Nanum Pen Script 'Congre'. 작은 크기(32·16px 아이콘)는 잉크 사각 위 흰 쪽지 + 재생 `M41 37l22 13-22 13z`, 빨간 물결 생략. 최종본은 글자를 도형으로 바꾼 SVG라 글꼴 없이도 같게 보인다. 앱 머리글(BrandName), 파비콘·apple-icon, OG 이미지, logo.png, 메일 머리글 이미지에 쓴다.
- **근거**: 2026-10-06 로고 시안 4종(A~D) 중 Ray가 D를 골랐고, 빨간 펜 글씨를 포함한 지금 모양 그대로 확정했다. 그전에는 앱(Cormorant 기울임·주황), 랜딩 첫 페이지(Pretendard 기울임·C만 주황), 요금·소개·FAQ(Cormorant·C만 금색), 공유·참가자(금색)로 로고가 4가지였다(F10).
- **영향**: OG 이미지는 두 벌이다. 앱 `public/og-image.png`는 행사 공용판(모든 초대 링크·카카오 공유 카드의 대체 그림이라 결혼식 단어를 넣지 않음), 랜딩 `deploy/images/og-image.png`는 결혼식판("결혼식 방명록, 이번엔 영상으로"). 영상 끝 화면 로고 카드는 보류(D3).
- **출처**: 핸드오프 2026-10-07 5장 F10, 6장 로고 D.

## 2026-10-07 — 디자인 토큰 교체 (롤링페이퍼안)

- **결정**: 앱 전체 색·글꼴·버튼 모양을 롤링페이퍼(영상 방명록)안 기준으로 바꾼다. 바탕 #EEF4FB, 잉크 #1F3C9C(hover #152B73), 글자 #222222·#333333, 보조 글자 #4A5468, 종이 #FFFFFF, 선 #C9D6EA, 입력 테두리 #7F92B8(시안의 #8A9BC0을 입력칸 경계 대비 3:1 기준에 맞게 조금 진하게), 펜 4색(#C62828·#2E7D32·#6A1B9A·#8D4E00), 위험 #A61B1B. 글꼴 Gowun Dodum(UI 전부, 400 하나), Nanum Pen Script(펜 글씨). 버튼 모서리 6px, 카드 직각 1px 선. 움직이는 그라디언트 배경과 유리 효과 삭제. 변수 이름은 그대로 두고 값만 바꿨다(사용처 100곳 이상을 건드리지 않으려고).
- **근거**: 2026-10-06 Ray가 룩앤필 시안 5종 중 2번 롤링페이퍼를 골랐다(캔버스 https://claude.ai/artifact/4ABbmLf1Cg4JwHhtSohuad). 같은 날 390px 실측 화면 점검에서 나온 F1~F12(움직이는 배경, 유리 효과, 글자 간격 벌린 라벨, 영어 장식 라벨, 버튼 끝 화살표, 이모지, 주황, 로고 4종 등)를 Ray가 전부 승인했다. 두 글꼴은 Google Fonts OFL이라 상업·로고 사용이 가능하다(10/06 확인).
- **영향**: 주황 #E8794A와 옛 금색 #c8892c는 앱 화면에서 사라진다(영상의 인트로·아웃트로 글자 색 #c8892c는 렌더 확인이 필요해 다음 테스트 렌더 때). 다크 테마는 C4·C5에서 폐지.
- **출처**: 핸드오프 2026-10-07 5·6장, 화면 점검 시트 F1~F12.

## 2026-10-06 — F 규칙 (모든 화면에서 쓰지 않는 것)

- **결정**: 움직이는 배경, 유리 효과, 장식 그라디언트, 글자 간격 벌린 라벨, 제목의 한 구절만 색 강조, "단어 — 설명" 라벨, 영어 장식 라벨, 버튼 끝 화살표, 이모지, 테라코타 주황, 가운뎃점 나열 메타, "AI" 표현을 쓰지 않는다. 로고는 하나. 채운 버튼 = 주 동작, 테두리 버튼 = 보조, 위험 동작은 떨어뜨리고 색으로 구분. 예시 사진·영상에는 '예시' 표시.
- **근거**: 2026-10-06 화면 점검(라이브 랜딩 실측: 유리 효과 47, 그라디언트 49, 움직이는 요소 52, 글자 간격 라벨 39, 모서리 둥글기 13종)에서 AI가 만든 티가 나는 패턴으로 분류했고 Ray가 F1~F12 전부 승인했다.
- **출처**: 핸드오프 2026-10-07 3·6장.
