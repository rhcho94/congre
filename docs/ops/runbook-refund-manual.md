# 환불 수동 처리 절차서

> 근거: 2026-10-09 정찰(HEAD 기준 코드). 코드에는 토스 결제취소 API 호출이 없다(known-issues "환불 집행 코드가 없다"). `refundStatus`는 "환불 대상 확정"이지 "환불 완료"가 아니다. 실제 환급은 운영자가 토스 상점관리자에서 한다.
> **2026-10-19 확인**: 당일 전체취소는 상점관리자에서 된다(실측). 부분취소·정산 전 취소도 같은 경로로 된다(토스 상담). 취소한도를 넘으면 '취소액 입금'으로 처리한다 — 4절.

## 1. 언제 환불이 생기나 (약관 제10조의3)

| 구분 | 조건 | 금액 | 자동으로 되는 것 | 수동 |
|---|---|---|---|---|
| 지연 50% | 결제 완료(`paidAt`) + 4시간이 지나도록 `rendering` | 결제 금액의 50% | cron `check-render-deadlines`가 `refundStatus: "50"` 기록 + 호스트 메일·문자(refund_50) + 운영자 문자(CONGRE_INTERNAL_PHONE 설정 시) | 토스 취소 |
| 지연 100% | 결제 완료 + 48시간 | 전액 | 같은 cron이 `refundStatus: "100"` + refund_100 알림. 영상은 끝까지 완성해 전달 | 토스 취소 |
| 렌더 실패 | 엔진 실행 실패(FAILED·TIMED_OUT·ABORTED) → 이벤트 `closed` | 약관 제10조의3 ④ 회사 귀책 | `check-rendering`이 호스트에게 render_failed 알림 + 운영자 문자(2026-10-09~) | 재시도 또는 토스 취소. **cron의 4시간·48시간 환불은 `rendering` 상태만 보므로 실패 뒤에는 자동 확정이 없다** — 운영자가 판단 |
| 결제 후 렌더 시작 실패 | 결제 성공 페이지의 `render/start` 호출 실패(`renderFailed`) | 위와 같음 | 없음(호스트가 직접 재시작) | 위와 같음 |
| 호스트 변심 | — | 없음 | — | 환불 없음(decisions/infra.md 2026-09-22~24 결정 4) |

약관상 처리 기한: **환불 사유가 확정된 날부터 영업일 기준 3일 이내**(제10조의3 ⑧).

## 2. 사고를 아는 방법

1. 운영자 문자(`CONGRE_INTERNAL_PHONE`): 지연·환불 확정·렌더 실패 때 온다. Vercel 환경변수에 값이 있어야 한다 — 설정 확인됨(2026-10-10, Production·Preview).
2. Vercel 로그: `[cron] refund_50`, `[cron] refund_100`, `[cron/check-rendering] ... failed`.
3. Firestore `events/{eventId}`: `refundStatus`, `notifications.refund50NotifiedAt`, `notifications.refund100NotifiedAt`.
4. 호스트 문의(카카오톡 @congre / cs@rayne.co.kr).
5. 결제 확인 이상(Vercel 로그):
   - `[payment/confirm] failed to save paid status` — 토스 결제는 끝났는데 주문·행사 저장 실패(500 `SAVE_FAILED`). 주문은 `pending`. 호스트가 새로고침하면 재시도로 저장된다(코드 경로, 라이브 미확인). 그 사이 클립 수가 바뀌었으면 `stale`(known-issues "결제 저장 실패 뒤 클립 수가 바뀌면…").
   - `[payment/confirm] payment status unknown after request failure`, `[payment/confirm] already processed but not confirmed DONE` — 토스 결제 상태를 확정하지 못함(502 `PAYMENT_STATUS_UNKNOWN`). 주문은 `pending`. 토스 상점관리자에서 orderId로 결제 여부를 확인한다.

## 3. 처리 순서

1. **금액 확정**: Firestore `payments`에서 해당 이벤트의 `status: "paid"` 문서 → `orderId`, `amount`, `paymentKey`, `paidAt`. 50%는 `amount × 0.5`(원 단위 절사 여부는 토스 화면 기준).
2. **토스 상점관리자**에서 취소: 상점관리자 → 결제조회 → 결제수단 탭(신용·체크카드 / 계좌이체) → 해당 주문(orderId 또는 결제일·금액) → '취소하기'. 50%는 부분취소, 100%는 전체취소. *취소한도 초과 문구가 뜨면 '취소액 입금' — 4절.*
3. **기록**: Firestore 이벤트 문서에 수동 필드를 넣지 않는다(코드가 읽지 않음). 대신 `docs/ops/refund-log.md`(없으면 생성)에 날짜·이벤트 id·orderId·금액·토스 취소번호를 한 줄로 남긴다.
4. **호스트 안내**: 자동 메일은 "별도로 연락드리겠습니다"라고 했으므로 취소 완료 뒤 카카오톡(1순위) 또는 전화로 "취소 처리 완료, 카드사 반영 영업일 3~4일" 한 줄.
5. **재렌더 여부**: 50%·100% 모두 영상은 완성해 전달한다(약관·refund_100 메일 문구). 렌더가 멈춘 상태면 `docs/ops/runbook-render-stuck.md`로.

## 4. 토스 취소 규칙

### 확인됨 (2026-10-10, 토스 FAQ — Ray 전달)
- **신용카드**: 취소 수수료 없음. 고객에게는 청구액 전액이 취소되고, 가맹점에는 수수료를 뺀 금액이 지급액에서 차감된다.
  - 매입 전 취소(승인 취소)는 결제 당일만. 전체취소는 즉시, 부분취소는 영업일 3~4일.
  - 매입 후 취소는 통상 1년까지(카드사마다 다름), 영업일 3~4일.
- **계좌이체**: 환불 기한 180일, 실시간 환불. 원거래 수수료는 돌려받지 못한다.
- 경로: 상점관리자 → 결제조회 → 신용·체크카드 / 계좌이체 → '취소하기'.
- 이 서비스의 환불은 결제 후 4시간·48시간 뒤 확정되므로 대부분 **당일 50% 부분취소(3~4일)** 또는 **다음 날 이후 매입 후 취소(3~4일)**가 된다. 고객 안내는 "카드사 반영 영업일 3~4일".

### 확인됨 (2026-10-16, 실측 — 유료 시험 결제)
- 결제 당일 전체취소: 상점관리자 → 결제조회 → 해당 주문 → '취소하기' → 전체취소로 성공(10,000원). 2026-10-18에 1건 더 같은 방식으로 성공.

### 확인됨 (2026-10-19, 토스 1:1 상담 + 상점관리자 이용정보)
- 취소한도는 가맹점이 정하는 값이 아니라 토스가 계산하는 값이다: 정산 예정 금액 + 당일 승인 금액 − 당일 취소 금액(당일 지급 예정 금액 제외). 결제가 없으면 0원으로 보인다.
- 정산 주기: 신용·체크카드, 계좌이체 모두 결제 후 5영업일 입금(주말·공휴일이 끼면 늦어질 수 있음). 현재 한도는 상점관리자 → 이용정보에서 본다.
- 당일 부분취소(50%)도 한도 안이면 같은 경로로 된다.
- 한도를 넘으면: '취소하기' → 한도 초과 문구 → '취소액 입금' 버튼 → 계좌이체 또는 가상계좌로 취소 금액 입금 → 입금 즉시 취소 반영.
- 이 서비스의 환불은 결제 후 4시간(50%)·48시간(100%)에 확정되고 처리 기한이 영업일 3일이라, 기한 안에 처리하면 정산 전이다. '취소액 입금'은 처리가 늦어진 경우의 예외 경로다.
- 같은 MID(`congreamu1`)를 필드샷도 쓴다. 한도는 두 서비스 합계라 한쪽 취소가 다른 쪽 한도를 깎는다(2026-10-19 필드샷 결제 중 13,500원 → 취소 뒤 0원 관측).

### 아직 해 본 적 없음
- 당일 부분취소, 매입 후(정산 전) 취소, '취소액 입금' — 모두 실측 없음. 첫 사용 때 화면·소요 시간을 refund-log에 남긴다.

## 5. 알려진 구멍

- 재렌더 결제 뒤에는 `refund50At`/`refund100At`이 새로 기록되지만 `refund50NotifiedAt`/`refund100NotifiedAt`은 초기화되지 않아 두 번째 지연에는 환불 알림이 다시 나가지 않는다(2026-10-09 정찰). 등재만.
- 렌더 실패·시작 실패 뒤에는 자동 환불 확정이 없다(1절 표). 운영자 문자로 알고 수동 판단.
