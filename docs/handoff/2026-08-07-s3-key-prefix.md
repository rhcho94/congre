## 정찰로 확정한 사실
- **presign 라우트는 이미 잠겨 있었다.** 키를 서버가 조립하고, clip/thumb는 `sessionToken`, intro/outro는 Firebase ID 토큰 + `hostId === uid`를 본다. `fileName` 정규식 `/^[A-Za-z0-9._-]+$/`에 슬래시가 없어 경로 탈출도 막힌다. 구멍은 발급이 아니라 **"이미 만들어진 키를 나중에 받아 저장하는"** 두 라우트였다
- 게스트도 `sessionToken`(이벤트 단위 공유 시크릿)을 통과해야 한다. `eventId`만으로는 통과 못 한다. 이것이 프리픽스 검증이 성립하는 근거
- `videoS3Key`는 `${renderId}.mp4` 형식으로 버킷 루트에 있다. "이 버킷의 모든 키가 `events/`로 시작한다"는 명제는 거짓
- 대시보드 `patchInvite`는 필드를 하나씩만 보낸다. 미디어와 무관한 설정 저장 시 미디어 키가 실리지 않아, 옛 형식 키를 가진 이벤트가 파손될 경로가 없었다
- `s3Key`/`thumbKey` 쓰기 지점 3곳 중 클라이언트 입력을 저장하는 것은 `api/clips` 1곳뿐. cron 2곳은 서버 조립·기존 값 필터링
