## 발단 — 토스 보완 요청 (2026-08-24 수신)

> 영상 제작 후 7일 간 영상 다운로드가 가능한 점은 확인하였습니다.
> 다만 영상제작 기간에 대한 홈페이지 내 기재가 필요하여 요청드립니다.
> 홈페이지에 기재된 것처럼, 영상 제작 완료까지 10분 소요라면 추가 수정 불요합니다.

심사자가 본 "10분"은 메인 랜딩 히어로 카피("외주는 2주, Congre는 10분")였다.
상품 상세(`pricing`)와 결제 화면에는 제작 기간 표기가 한 글자도 없었다.
실측으로 확인 — 두 화면 모두 제작 기간·다운로드 기간·환불 규정 전무.

"10분"을 그대로 확약하면 지연 1건에 표시 위반이 된다. 코드상 10분은
`render/complete`의 완료/지연 분기 기준선이지 보장값이 아니다.

## 정찰 결과

### 약관·코드 3축 정합 (실측)

| 축 | 제작 기간 | 다운로드 기간 |
|---|---|---|
| 약관 | 제10조의2 ① "결제가 완료되면 즉시 제작 개시" | 제11조 ①2호 "완성본이 생성된 시점으로부터 약 7일" |
| 코드 | `render/complete` 10분 기준 분기 | `cron/cleanup:59` `v.doneAt` + 7일 |
| 화면(신규) | "결제 완료 즉시 시작, 통상 10분 이내" | "완성된 시점으로부터 약 7일" |

**다운로드 기산점이 결제가 아니라 완성 시점이다.** 토스 1차 회신의
"결제 후 7일" 확약은 제작이 결제 직후 개시되므로 항상 충족된다.
제작이 지연돼도 다운로드 창이 줄지 않는다.

### 환불 구간 (약관 제10조의3 ③, 코드 구현·실측 검증 완료)

- 4시간 이내 제공 → 환불 없음
- 4시간 초과 48시간 이내 → 50%
- 48시간 초과 → 100%. **③3호가 "환불 여부와 관계없이 제공을 계속 시도"를 명시**

환불 확정과 알림은 자동이나 PG 취소 API 호출 코드는 저장소에 없다.
실제 환급은 운영자 수동 처리(약관 제10조의3 ⑧ "영업일 기준 3일 이내").
따라서 화면 문구는 "환불"이 아니라 **"환불 확정"**으로 적었다.

### "우선 처리" — 코드 근거 없음 (신규 발견)

- `render/start`: `plan`은 결제 검증(L50-55)과 `createRender` 전달(L179)에만 쓰임
- `shotstack.ts`: `plan === "free"` 분기 2곳 모두 결과물 내용(폰트·워터마크).
  Shotstack API 호출에 `priority`·`queue` 파라미터 없음
- `check-rendering`: `plan` 식별자가 파일에 등장하지 않음. 스냅샷 순서대로 순회
- `priority|queue|Priority|Queue` src 전체 검색 → Shotstack 상태값 주석 1건뿐

유료·무료의 실제 차이는 워터마크와 폰트다. 처리 순서 차이는 구현돼 있지 않다.
