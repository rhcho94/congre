### 3. 세 클로드 영역 격리 학습
- 채팅 클로드 / CD / CC는 각각 독립 컨텍스트. 한 클로드가 보는 것 = 자기 채팅창에
  직접 입력된 것 + 자기 도구로 가져온 것뿐
- 다리 역할은 전부 운영자. 클로드끼리 직접 대화 못 함
- CD ↔ CC 자동 다리: Export → "Handoff to Claude Code" 명령 또는 zip. 운영자가 명령
  복사해 CC에 붙여넣는 수동 전달
- 핵심 룰 (CLAUDE.md에 박힘): 결정·실행·기록은 영역 분리. CD 안에서 다 섞지 말 것
  (turn 한도 도달 시 휘발)

### CD 첫 사용 사이클의 흔한 사고 패턴 (운영자 자기 진단 일치)
한 도구 안에서 시각·결정·실행·기록 다 섞으면 turn 한도 도달 시 결정·기록이 휘발됨.
운영자가 "처음이라 채팅·디자인 역할 구분 못함"이라고 직접 짚었고 그게 정확한 진단.
거의 모든 신규 도구 도입 사이클에서 발생하는 자연스러운 패턴. 다음부터: 시각은 CD,
영구 결정은 채팅 클로드에 알려 docs에 박기, 실행은 CC.
