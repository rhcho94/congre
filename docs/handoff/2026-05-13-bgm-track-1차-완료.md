## 본 세션 학습

### 1. 확인-실행 분리 강제 문구 효과

CC가 1·2회차에 "작업 전 확인 사항 보고 후 사용자 승인 대기" 지시를
누락하고 통합 진행. 3회차에 프롬프트 마지막 단락에 **"이전 두 회차
모두 누락" + "executing-plans 스킬이 단계 통합으로 작동하더라도 본
프롬프트가 명시적 분리 요구"** 추가하니 준수.

**다음부터 적용**: 확인-실행 분리 중요한 작업엔 "이전 회차 누락 패턴
+ 본 회차 분리 우선" 단락을 표준 템플릿으로. 단순 작업엔 불필요
(오버헤드).

### 2. 라인 번호 추정 금지

채팅 클로드(본 세션)가 사양에 line 107~111 적었지만 실제 117~121.
운영자 첨부 코드 파일엔 라인 번호 없었음 → 눈대중 추정한 결과.

이번 건은 CC가 정확히 분간 ("구조는 정합, 라인만 어긋남")해서 사고
없었지만, 향후 CC가 어긋남 발견 시 "어느 쪽 따를지 확인 필요"로 가서
시간 소모 위험.

**다음부터 적용**: 사양에 라인 번호 적을 때 "추정"이라고 명시하거나,
차라리 라인 번호 빼고 **함수명·변수명·블록명**으로만 지칭.

### 3. Shotstack volume은 선형 스케일 추정 (실측 근거)

volume 0.3 → 0.2 (33% 감소): 청각 변화 거의 못 느낌 (음성 묻힘 여전)
volume 0.2 → 0.1 (50% 감소): 청각 변화 명확 (5개 항목 모두 통과)

청각은 로그 스케일로 인지하는데 Shotstack volume은 선형 추정. 0.3→
0.2는 dB 단위로 미미 (-3.5dB), 0.2→0.1은 명확 (-6dB).

**다음부터 적용**: Shotstack 음량 조정 시 33% 이하 변경은 청각상
미미할 수 있음. **큰 폭(50% 이상) 변경 우선** 후 미세 조정.

### 4. 화면 표시 한계 — 코드 블록 중첩

본 세션 프롬프트 작성 시 바깥 코드 블록 안에 안쪽 코드 블록(커밋
메시지)을 ``` 으로 감싸니 마크다운이 바깥 블록 종료로 해석. 운영자가
"두 블록으로 보임" 질문 → 재작성 시 안쪽 백틱 제거.

**다음부터 적용**: 프롬프트 내 코드 블록 중첩 회피. 커밋 메시지나
예시 코드는 인라인(`single backtick`) 또는 들여쓰기로 표시. ``` 중첩
금지.
