## 2단계 사양 확정본

### 데이터 모델

- Clip: `uploaderName: string` (1~20자, required), `uploaderPhone: string` (010+8자리 숫자, required)
- events: `organizerPhone` 형식 검증 추가 (010+11자리)
- 식별 키: `eventId + uploaderPhone + uploaderName` 복합

### 중복 정책

- 다른 전번 → 통과
- 같은 전번 + 다른 이름 → 통과 (친구 폰 돌려쓰기)
- 같은 전번 + 같은 이름 → 차단 ("이전 영상과 다른 이름을 입력해주세요")
- 에러 코드: `DUPLICATE_NICKNAME` → `DUPLICATE_UPLOADER`

### 입력 UX

- stage 이름: `nickname` → `uploader`
- 인풋 2개: 이름 (text, maxLength 20), 전번 (tel, maxLength 13, 사용자 자유 입력 → 클라이언트 정제 후 검증)
- 전번 정규식: `/^010\d{8}$/` (정제 후)
- sessionStorage 키: `congre-uploader-${eventId}`, 값 JSON `{name, phone}`
- reRecord (하나 더 올리기): uploader stage 직행, 이름·전번 둘 다 미리 채움, 사용자가 직접 수정

### API

- `GET /api/clips/check?eventId=&phone=&name=` (3 파라미터 복합)
- `POST /api/clips`: body에 uploaderPhone 추가, 정제·검증·복합 중복 체크
- `GET /api/host/clips`: 응답에 uploaderPhone 추가
- `POST /api/events`: organizerPhone 검증 추가

### SMS 발송 (참가자)

- 트리거: `src/app/api/cron/check-rendering/route.ts` Shotstack done 직후
- 흐름: clips Firestore 조회 (excludedAt: null) → distinct uploaderPhone → 각 phone에 notifyParticipantResult
- 본문: `[Congre] '{eventTitle}' 결과 영상이 준비됐어요: {videoUrl}` (이름 없음)
- 멱등성: events 문서에 `participantNotifiedAt` 필드 추가, 발송 직전 체크
