## 본 세션 학습

- **CC가 보고 마지막에 자체 합계 끼워 넣는 패턴 재발**: cont2·cont3에서
  학습 항목으로 명시했으나 본 세션 의제 A 보고에서 "11파일, +21/-666"
  자체 합계 추가. 사양 명시("git diff --stat 그대로, 자체 합계 표 만들지
  말 것")로도 잡히지 않음. **다음 세션부터는 사양 문구 외에 보고 검토
  단계에서 한 번 더 확인 룰**. 채팅 클로드 검증 단계에서 합계 위반 발견
  시 정정 요청.

- **str_replace 부분 매칭 실패의 안전망은 빌드**: 의제 A 진행 중
  initialContent 일부 삭제만 부분 수행으로 `</p>` 고아 JSX 잔존 사례
  발생. 빌드 단계에서 잡혀 즉시 재정리됨. **3단계 실행 사양에 "빌드
  통과 확인" 명시한 것이 안전망 역할로 작동**. 이 단계 생략 금지.

- **probe API 도입 폐기 결정 — 정찰이 운영자 사전 결정을 뒤집은 사례**:
  cont3에서 운영자가 "보기 1 probe API 도입 우선" 결정했지만, 본 세션
  정찰에서 probe의 WebM·비용 한계 발견 후 보기 2(overlay 폐기)로 변경.
  **정찰 단계가 운영자 사전 결정을 뒤집을 수 있는 정보 채널임을 입증**.
  사양 결정 전 정찰 한 라운드는 라운드 ② 학습 이래 안정 작동 중.

- **CC 정찰이 채팅 클로드 정찰의 누락 영역을 잡은 사례**: 의제 A 정찰
  1단계 프롬프트가 handleCopy로 좁아져 handleKakaoShare 등 다른 공유
  버튼 영역 누락. CC가 F영역(handleKakaoShare /share URL) 추가 발견.
  추가 정찰(G영역) 한 라운드로 다른 SNS 공유 버튼 4개 확인. **채팅
  클로드 정찰 프롬프트 작성 시 영역 좁히기 vs 넓히기 트레이드오프
  재확인 필요**. cont3 라운드 ③의 사전 정찰 깊이 학습과 같은 영역.

- **invite-urls API 이름 어색함은 별도 작업으로 분리**: 초대장 제거 후
  "invite-urls"라는 이름이 인트로/아웃트로 미디어만 다루는 상태. YAGNI
  원칙으로 리네임 작업 별도 분리. 트리거 발생 시(예: 새 미디어 종류
  추가 시점) media-urls 등으로 리네임 검토. **현재는 코드 동작에 영향
  없으므로 보류**.
