## 5. 정찰에서 찾은 위험 4건 (known-issues 등재 후보, 아직 안 고침)
1. render/start 중복 시작 방지 없음 — status가 rendering·done이어도 다시 시작, 엔진 실행 2개 생김(`render/start/route.ts` 전체에서 status 조건은 50행 환불 잠금뿐).
2. confirm이 트랜잭션 아님 — 동시 요청 2개가 둘 다 pending을 읽고 토스 승인으로 갈 수 있음(`confirm/route.ts` 25·37 읽기, 121 쓰기). 토스 승인 성공 + 저장 실패(SAVE_FAILED) 뒤 새로고침도 승인을 다시 보냄. 같은 paymentKey 두 번째 승인에 토스가 어떻게 응답하는지 미확인.
3. render/start가 엔진 시작(198) 뒤 이벤트 저장(214)을 try로 감싸지 않음 — 저장 실패 시 엔진은 돌고 이벤트는 rendering이 아니라 cron이 못 집음.
4. 결제 성공 화면이 render/start 실패 코드를 안 보여 줌(`page.tsx` 124-127). 원인은 Vercel 로그 `[render/start]`에만.

한 번 결제하고 탭 하나로 여는 정상 사용에선 드러나지 않았다. 실고객 전에 무엇을 고칠지 Ray 결정.
