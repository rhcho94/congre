## 이번 세션에서 뒤집힌 것 4건

1. **8/13 핸드오프의 ★ 지적이 틀렸다.** "cron 1일 1회라 25시간 만에
   삭제될 수 있다 → 컷오프 자체를 올려야 한다"는 부등호 방향을 반대로
   읽은 것이다. 비교식이 `participantNotifiedAt <= now - cutoff`라
   컷오프 경과 전에는 어느 회차에서도 조건이 참이 되지 않는다. 배치는
   삭제를 **늦추는** 방향으로만 작동한다. 실제 보관 구간은
   `[컷오프, 컷오프+24시간]`. 안전마진 없이 정확히 48로 두었다.
2. **무료 이벤트 기산점은 구멍이 아니라 표기 누락이었다.** 마감 버튼
   클릭 시점이 사양이었고 문서가 유료만 적고 있었다. 다만 그 시각을
   담는 필드가 코드에 없어서, 표기를 고치자 진짜 구멍이 드러났다.
3. **처리방침에서 손댈 행이 1개가 아니라 2개였다.** `:127` 참가자 정보
   행도 같은 "약 24시간". 8/13 핸드오프는 `:131`만 적었다.
4. **제5조 위탁 표에 토스페이먼츠가 없었다.** 약관 제10조의2 ③은
   8/13부터 "결제대행 업무를 토스페이먼츠에 위탁합니다"를 게시 중이었다.
   항목 ⑬은 단순 추가가 아니라 **불일치 해소**였다.

## 실측으로 확정된 것 4건

- **cron은 UTC.** Vercel Settings → Cron Jobs 화면에
  "All scheduled times use the UTC timezone." 명시.
  `"0 18 * * *"` = 18:00 UTC = KST 03:00. 토글 Enabled, 플랜 Pro.
- **`closedAt`이 렌더 시작보다 먼저 박힌다.** 실측: `closedAt` 16:08:35
  → `renderStartedAt` 16:08:38. `rendering` 이벤트는 `closedAt`을
  물려받는다. eye가 추론으로만 적었던 것이 데이터로 확인됐다.
- **D-3 루프 실동작 확인.** cleanup 수동 실행 3회 전부 HTTP 200, 724ms.
  `[cleanup] closedAt 없음, 건너뜀:` warn 3건 + `clipsDeleted: 0`.
  가드가 실제 데이터에서 의도대로 걸렸다. 3회 실행 결과가 동일해
  멱등성도 확인됐다.
- **`api/user/delete`는 `payments`를 참조하지 않는다.** 참조 컬렉션은
  `events`·`clips`·`users` 3개뿐. 초안 코드작업 ⓐ는 불요.
