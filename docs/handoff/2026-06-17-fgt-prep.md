# FGT(무료 실사용 테스트) 준비 — 영구 작업 문서

> 이 문서는 FGT 절차 전체를 담는 영구 문서다. 세션마다 갱신한다.
> 1차 소스는 항상 라이브·DB·git 코드. 이 문서는 그 파생물이며, 라이브와
> 어긋날 수 있으니 현재 상태가 쟁점이면 코드/라이브를 직접 확인할 것.
> 최종 갱신: 2026-06-17

---

## 1. FGT 정의·목표

- **FGT** = 결제 없이 "무료 루틴만"으로 실제 사용자/행사 대상 테스트.
- **배경**: 토스페이먼츠 인증이 약 1개월 지연(메일 통보). 결제 게이트
  (Phase 3)가 외부 절차에 막혀 있어, 그 전에 무료만으로 서비스 한 바퀴가
  도는지 검증한다.
- **핵심 방향**(Ray 결정):
  - 유료·결제 경로는 안내(비활성화 + 문구)로 막는다.
  - 무료 루틴은 끊김 없이 돌게 한다.
  - FGT 기간 한정으로 성인만 가입(자가신고 체크박스).

---

## 2. 완료 조건 (Definition of Done)

FGT 시작 가능 상태 = 아래가 모두 충족될 때:

1. 무료 한 바퀴가 끊김 없이 돈다: 가입→이벤트 생성→QR/링크→참가자
   업로드→마감→렌더→완성 알림→회수.
2. 유료 옵션이 막혀 있다(사용자가 실수로 유료 못 만듦 + 운영자 비용 사고
   방지 서버 가드).
3. 가입 시 "만 19세 이상" 자가신고 체크박스가 필수로 동작한다.
4. cron(렌더 완료 폴링)이 실제로 가동 중임이 확인된다. ← 이게 안 되면
   영상이 안 나옴(최우선 점검).

## 3. 정찰로 확정된 사실 (1차 소스 = src/ 코드, 2026-06-17 정찰)

### 축 A — 유료·결제 분기점

- 무료/유료 분기는 **이미 완전 구현**돼 있고, **결제 처리만 없음**.
  - 타입: `src/lib/events.ts` L7 `EventPlan = "free" | "paid"`,
    `src/lib/plans.ts` L1.
  - 생성 폼: `src/app/dashboard/create/page.tsx` L78–81 plan 라디오 2개,
    L274–298 라디오 UI, L301~ free/paid 분기.
  - 서버 검증: `src/app/api/events/route.ts` L80–107
    (plan·maxClips·maxClipSeconds 검증).
  - 업로드 한도: `src/app/api/clips/route.ts` L56–62
    (free=5클립 강제, `PLAN_CLIP_LIMITS.free`).
- 가격식: `src/lib/plans.ts` L21–23 `Math.max(maxClipSeconds*clipCount*100, 10000)`.
  화면 표시: `dashboard/create/page.tsx` L359. 코드에 이미
  "지금은 결제하지 않습니다"(L364) 안내 존재.
- **결제 게이트 0건**: close/route.ts·render/start/route.ts에 결제 검증 없음.
  `toss/payment/billing` 키워드 grep 0건 = Phase 3 미구현 확정.
- 무료/유료 결과물 실차이 = **워터마크뿐**.
  `src/lib/shotstack.ts` L250–263 (free면 "made by Congre" 삽입).
- **현 상태: 유료 선택해도 결제 0원으로 완성본 나옴** → FGT에서 막아야 함.

### 축 B — 무료 루틴 완결성

- B1 가입→생성→QR: **이미 됨**. 생성 후 업로드 링크 자동 생성
  (`dashboard/create/page.tsx` L158), QR `QRCodeSVG`(L424).
- B2 참가자 업로드: **이미 됨**. presigned URL→S3 PUT
  (`upload/[eventId]/page.tsx` L281–284), 무료 한도 서버 강제.
- B3 마감→렌더: **수동 마감**(자동 마감 코드 없음). 호스트가 "마감하기"
  버튼(`events/[eventId]/page.tsx` L812)→close→곧바로 `callRenderStart`
  →Shotstack 렌더 즉시 트리거.
- B4 렌더 완료→회수: **이미 됨, 단 cron 폴링 의존**.
  `api/cron/check-rendering/route.ts`가 status="rendering" 폴링→done 시
  알림 발송(호스트 이메일+SMS, 참가자 SMS). 완성본: 호스트
  events 화면 / 참가자 share 화면.
- B5 실패·예외: **부분만 됨**. 업로드 3회 재시도+에러 메시지 있음.
  **사각지대**: cron 안 돌면 status="rendering"에서 멈춤, 클라이언트가
  적극 폴링 안 함, cron 실패 알림 채널 없음. → §2-4 점검 필수.

### 축 C — 연령·본인확인 현황

- C1 가입 필드: 이메일·비번·이름·전화번호 4개 + 약관·개인정보 체크박스 2개.
  **연령 관련 필드 없음**(`signup/page.tsx`).
- C2 약관 동의: **이미 됨**. 개별 체크박스 2개(L153–184), 둘 다 필수.
  state `termsAgreed`(L34)·`privacyAgreed`(L35), `canSubmit`(L39)로
  버튼 disabled 차단. "전체 동의" 묶음 아님.
- C3 제출 핸들러: `handleSubmit` L41–62. 검증 추가 위치 = L39 canSubmit
  조건에 `ageAgreed &&` 추가(기존 패턴과 일관, 추천).
- C4 본인확인/SMS 인증: **없음**. 이메일 링크 인증만 존재(auth.ts L41).
  전화번호는 알림 수신용 입력만, 인증 절차 없음. SOLAPI는 알림 전용.

## 6. 알려진 한계·나중 과제 (FGT엔 영향 없음, 정식 운영 시 검토)

- **약관 동의 사실이 DB에 안 남음**: `signUpWithEmail`이 동의 여부를
  저장 안 함(auth.ts). 화면 체크만. 정식 운영 땐 동의 이력(시각 등) 기록 필요.
- **전화번호 미인증**: 입력만 받고 본인확인 없음. ①(휴대폰 본인확인)으로
  갈 때 손볼 지점.
- **자가신고의 한계**: 19세 체크박스는 거짓 체크 가능. 진짜 차단 아님.
  FGT 목적(법적 최소 방어+흐름 검증)엔 충분.
- **랜딩 git 외부 트랙**: deploy/ 변경은 문서 자동 기록 안 됨. 드리프트 주의.
