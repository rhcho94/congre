## 자체 학습

- **외부 API 구조 추측 금지 패턴**: 커밋 1에서 Shotstack DELETE 엔드포인트를 일반 RESTful 패턴으로 추측해 사양에 박음. 실제로는 Edit/Serve/Ingest 3개 API 분리, 자산 삭제는 Serve API에서 두 단계 절차. 외부 API는 web fetch로 docs 직접 확인이 정답. 커밋 1.5로 교정. 호출처 0건이라 사고로 이어지진 않았으나, 라이브 운영 후 발견됐으면 첫 cleanup 사이클 통째 실패할 뻔.
- **truncate 출력 검증 누락 위험**: CC 보고가 50줄 넘는 신규 파일에서 본문 truncate되어 출력. 빌드 통과 + 사양 라벨 매핑만으로 검증 시도했으나 본문 직접 못 봄을 발견. 추가 정찰 프롬프트로 본문 + 4개 답변 받아 검증 통과. 다음 사양부터는 신규 파일 50줄 이상이면 보고 형식에 "전체 코드 인용 필수" 명시.
- **데이터 위치 추측 검증 누락**: 채팅 클로드(나)가 사양 짤 때 `participantNotifiedAt`을 clips 컬렉션 필드로 머릿속에서 합쳤음. 실제로는 events.notifications 안 필드. PR 1 정찰 결과를 핸드오프에서 다시 확인 안 한 채 추측. CC 정찰에서 정정됨. 데이터 위치는 매번 코드 확인.
- **트레이드오프 표 결정변수 명시 패턴**: 운영자가 "분리 vs 통합" 1차 결정에서 분리 → push 순서 제약 보고 통합으로 번복. 첫 추천 근거(거짓 고지 창)가 결정변수였는데 첫 결정 시점에 충분히 안 와닿았음. 다음부터 트레이드오프 표 옆에 "이 변수가 결정적이면 X로 기울 것" 한 줄 명시.
- **위험 영역 단계 분리 효과**: CRON_SECRET 재발급은 3개 cron 동시 영향. 단계 1(저장 확인) → 단계 2(재배포) → 단계 3(기존 cron 깨졌는지 확인) → 단계 4(cleanup 수동 호출) 분리. 한 단계 실패 시 다음 단계 진입 안 함. 운영자가 "복잡하다"고 미루고 내일 진행 결정 — 위험 영역에서 단계 늘어나는 건 정상.
- **운영자 발견 사고 분기 처리**: 검증 데이터 준비 중 호스트 화면 사고(다시하기 버튼 race) 발견. 본 PR 범위에 통합하지 않고 별도 PR로 분리 결정. 정찰 안 된 영역을 큰 PR에 끼우지 않는 패턴.
