## 4. 결정·수정 (`b9560d1`)
- Ray B안: 서버 정규화 + 화면 문구(2파일). A안(문구만)은 하이픈 거부가 남고, C안(공용 함수로 통합)은 6~7파일. 지금 고장 난 곳은 생성 화면 하나라 C안은 YAGNI로 보류(R3).
- `api/events/route.ts`: `const organizerPhoneClean = typeof organizerPhone === "string" ? organizerPhone.replace(/\D/g, "") : "";` 정규식 검사와 저장 모두 이 값. 문자열이 아닌 입력은 500 대신 INVALID_PHONE(400).
- `dashboard/create/page.tsx`: INVALID_COUPON과 같은 형식(alert + return)으로 INVALID_PHONE 분기. 문구 "휴대폰 번호는 010으로 시작하는 11자리 숫자로 입력해주세요."(가입 화면 문구와 같음).
- `+82` 입력은 계속 거부(다른 API와 같음).
- axe 1차 정지: 사양의 사전 확인 (a)에 걸렸다. `:77`은 값이 비었는지만 보고 문자열을 보장하지 않아 `.replace`가 500을 낼 수 있었다. typeof 가드로 사양을 고쳐 재실행.
- 선언 줄은 사양("필수 체크 블록 다음")과 달리 검증 바로 위에 들어갔다. 조건(필수 체크 뒤, 검증 앞)은 충족해 그대로 둠.
- CRLF 유지(route.ts 185→186, page.tsx 552→556, CR = LF).
- 커밋 본문에 CC가 Co-Authored-By 줄을 덧붙임(저장소 관행).
