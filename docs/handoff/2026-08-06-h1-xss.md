## 처리 완료 — H-1 저장형 XSS

원 경로: presign이 클라이언트 `fileType`을 무검증으로 ContentType 서명 → og-image가 미인증으로 그 ContentType 그대로 재전송 → 브라우저가 `app.congre.kr` 오리진에서 공격자 HTML 실행 → 같은 오리진 Firebase ID 토큰 탈취. 24시간 CDN 캐시가 붙어 원본 삭제 후에도 하루 배포.

3중 방어:
1. `presign/route.ts` — kind별 MIME 화이트리스트. clip·thumb는 목록 대조, intro/outro는 `image/`·`video/` 접두 + `image/svg+xml` 명시 거부. 400 `INVALID_CONTENT_TYPE`. 이벤트 조회보다 앞(DB 왕복 전 차단)
2. `og-image/[eventId]/route.ts` — 응답 직전 S3 ContentType 재검증. 검사를 `transformToByteArray()` 앞에 배치해 거부 대상은 다운로드조차 안 함. `X-Content-Type-Options: nosniff` 부착
3. `next.config.ts` — `headers()` 신설, `source: "/:path*"` 전 경로 nosniff

## 세션 중 발견·수정한 사양 결함
초안 사양의 SVG 차단이 단순 문자열 비교라 `image/SVG+xml`·끝 공백 변형으로 우회 가능했음. MIME이 대소문자 무구분 규격인 점을 놓친 것. 후속 사이클에서 비교 전 `.trim().toLowerCase()` 정규화 추가. **서명값·PutObjectCommand·presign 로그는 원본 유지** — presign 서명 Content-Type과 브라우저 PUT 헤더가 글자 단위로 일치해야 업로드가 성립하기 때문. 검증관 입력 6종 대조로 svg 3변형 + text/html 거부, png 대소문자 2종 통과 확인.

- **DevTools 네트워크 탭은 "로그 보존"이 켜져 있으면 옛 항목을 계속 보여준다.** 새로고침 3회에도 같은 Date·X-Vercel-Id가 나온 것이 단서였음. 헤더 1개 확인은 `Invoke-WebRequest` 한 줄이 훨씬 빠름
