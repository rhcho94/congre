### 2. BGM loop 전환 (해법 B)
- soundtrack loop 미지원 확정(공식). audio clip으로 같은 src를 start=i*(D-0.5) 직렬 배치, 마지막 조각 length=min(D, totalDuration-start)로 영상 끝 정확히 맞춤(overflow 없음). soundtrack 키 제거.
- 이음새: stage 3버전 실측(무fade / clip transition fade / 0.5s 겹침)에서 0.5s 겹침이 가장 깔끔 — 운영자 청취. (transition:fade는 audio에 안 먹음 = V1과 동일하게 들림.)
- probe: render/start에서 BGM presigned URL은 항상, 비디오 intro/outro presigned URL은 mediaType==="video"일 때만 probe. 이미지(5)·텍스트(3)·참가자 클립은 길이 이미 앎 → probe 안 함.
- 전체 길이 totalDuration = clipsTotal + introLen + outroLen. 기존 start="auto" 누적 끝과 일치 검산 완료.
- 회귀 안전: probe 실패 시(또는 비디오 intro/outro 길이 미상 시) loop 폐기하고 기존 timeline.soundtrack 폴백. "끊겨도 무음보단 나음" + 잘못된 길이로 loop 끊는 위험 회피.

## 핵심 사양 사실 (다음에 BGM/probe 만질 때)
- probe 엔드포인트: GET https://api.shotstack.io/{stage|v1}/probe/{URL인코딩}, 헤더 x-api-key. ffprobe 기반. mp4 duration 정상 반환(WebM만 미반환 — 2026-05-12 폐기 사유는 WebM 한계였음). presigned S3 URL(쿼리스트링째 encodeURIComponent) 그대로 200 통과. 크레딧 표에 probe 항목 없음 = 비용 없음으로 보임.
- audio clip의 volume은 clip 레벨이 아니라 asset 안에. clip 레벨 volume은 Shotstack 400 거부. (이번 버그 71f1a18. soundtrack 객체의 volume과 위치 다름.)
- 코드 위치: probeDurationSec는 src/lib/shotstack.ts에 export(env stage/v1 분기 같이 있음). BGM loop 배치·canLoopBgm·폴백도 createRender 안. probe 3개 병렬 호출은 render/start/route.ts presigned 3개 직후.
- 환경: .env.local은 SHOTSTACK_ENV=stage + SHOTSTACK_API_KEY(이 키로 stage 인증 정상). NEXT_PUBLIC_APP_URL은 .env.local에 없음(프로덕션 Vercel에만). 프로덕션 렌더/probe는 자동으로 /v1.
