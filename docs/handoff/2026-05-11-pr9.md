## 다음 세션 진입점

### 커밋 5 사양

**대시보드 상세 페이지(`src/app/dashboard/events/[eventId]/page.tsx`)에
"초대장 작성" 섹션 추가.**

#### 입력 필드
- welcomeText (text input, maxLength 120, optional)
- coverImageUrl (이미지 1장 업로드, optional)
- galleryUrls (이미지 최대 5장 업로드, 동적 추가 버튼 방식, optional)

#### 이미지 업로드 흐름
- 클라이언트에서 getPresignedUrl(eventId, fileName, mimeType, 'invite')
  호출 (커밋 2에서 추가된 kind='invite' 사용)
- S3 PUT으로 직접 업로드
- 업로드 성공 시 반환된 key를 events 문서의 해당 필드에 저장
  (PATCH API 신설 또는 기존 update 라우트 활용 — 정찰 필요)

#### 이미지 검증
- 파일 타입: image/* only
- 파일 크기: 단일 파일 상한 (10MB 정도, 정찰 후 결정)
- 해상도·비율 검증 없음 (YAGNI)

#### 갤러리 UI
- "+ 사진 추가" 버튼 방식 (5장 도달 시 버튼 숨김)
- 각 사진 옆 "삭제" 버튼

#### 미리보기 버튼
- "미리보기 열기" 버튼 → /invite/[eventId] 새 탭 (target="_blank")
- 다 비어있으면 버튼 비활성 또는 안내 텍스트
  ("초대장 비어있음 — 게스트는 업로드 페이지로 바로 이동")

#### 정찰 필요 항목 (다음 세션 첫 작업)

     있음 — 더 자세한 구조 확인)
   - 어디에 "초대장 작성" 섹션 배치하는 게 자연스러운지
2. 기존 events 문서 업데이트 API 존재 여부
   - PATCH/PUT 라우트가 있으면 재사용, 없으면 새로 만들지 또는 신설할지

## 자체 학습

- **사양 결정 시 코드 작성자 관점 ≠ 호스트 관점**: 커밋 3에서
  welcomeText를 인트로/아웃트로 위 별도 섹션으로 배치하면서 "섹션
  헤더로 구분됨"이라 판단했으나, 호스트 입장에선 비슷한 입력 3개가
  줄줄이 이어진 한 화면으로 읽힘. 시각적 거리(다른 페이지)가 의미적
  거리(다른 용도)를 만든다. 다음 사양 결정 시: "사용자가 첫 화면에서
  어떤 그룹으로 묶일까?"를 페이지 단위로 먼저 확인.

- **시퀀스 의존성 정찰을 한 커밋 미뤘음**: 커밋 2 사양 잡을 때 S3 키
  패턴을 `events/{eventId}/invite/...`로 정했는데, eventId가 언제
  생기는지(이벤트 생성 전인지 후인지)를 그때 확인 안 함. 커밋 3 정찰에서
  발견되어 사양 재조정 필요해짐. 다음부터 키 패턴 결정 시 "이 변수가
  언제 존재하는가" 시퀀스를 같이 확인.

- **"기존 패턴 따름"이라 하지 않고 추측으로 메움**: 커밋 3 사양에
  "글자 수 카운터 없음, 일관성"이라 명시했는데, 인트로/아웃트로에 이미
  카운터가 있었음. 정찰 결과로 확인되지 않은 디테일을 추측으로 채움.
  다음부터 "확인 안 된 디테일은 CC가 기존 패턴 따르도록 위임"으로
  처리.

- **혼동 가능한 표현 주의**: "기존의 ~"라는 운영자 표현을 "사양 안의
  fallback"으로 잘못 해석. 운영자는 "트랙 2-B 도입 이전 흐름"을 의미.
  표현 모호하면 두 해석 다 제시하고 확인받기.

- **CC 자체 권고가 사고 회피에 결정적**: 커밋 3 정찰 보고에서 CC가
  "eventId 시퀀스 문제"를 추가 발견으로 짚어줌. 만약 그 보고 무시하고
  실행 갔으면 임시 prefix 또는 다른 우회로 가서 known-issues에 새
  사고 패턴 추가됐을 것. CC 정찰 보고의 "추가 발견 / 결정 필요" 섹션은
  진지하게 검토.
