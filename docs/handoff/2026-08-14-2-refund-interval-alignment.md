## 코드 변경 내역 (`6e18ddd`)

### `api/payment/confirm/route.ts`

`paidAt`을 상수로 한 번 뽑아 세 값이 같은 시계를 쓰게 했다.

```
const paidAt = Timestamp.now();
payments/{orderId}.paidAt      = paidAt
events/{eventId}.refund50At    = paidAt + 4시간
events/{eventId}.refund100At   = paidAt + 48시간
events/{eventId}.closedAt      = FieldValue.serverTimestamp()  (무변경)
```

`closedAt`은 손대지 않았다. 클립 7일 삭제 기산점이 여기 걸려 있고
그건 8/14 (1) 세션 사양이다.

### `api/render/start/route.ts` — 4줄 삭제

| 삭제 | 사유 |
|---|---|
| `refund50At` 계산 | 계산 주체가 confirm으로 이관 |
| `refund100At` 계산 | 〃 |
| `notifications.refund50NotifiedAt: null` | 재렌더 시 "과거 시각 + 플래그 null" 조합 차단 |
| `notifications.refund100NotifiedAt: null` | 〃 |

**남긴 것**: `refundStatus: "none"`, `renderStartedNotifiedAt`,
`renderCompletedNotifiedAt`, `renderDelayedNotifiedAt`,
`participantNotifiedAt`. 뒤 4개는 재렌더마다 리셋되는 게 맞다.

### `emails/refund-100.ts:26`

## 실측으로 확정된 것 2건

- **`status == "rendering"` 문서 0건.** push 전 Firestore 콘솔 쿼리
  빌더로 `/events` + `status == "rendering"`(문자열, 한도 100) 조회 →
  "일치하는 결과 없음". cron 조회 조건이 `status == "rendering"`
  하나뿐이므로, 구 공식 값이 남은 문서가 있더라도 알림 경로에 도달하지
  않는다. 기존 문서 영향 없음으로 확정.

- **계산식과 실측값이 서로를 확인했다.**
  `renderEstimateMin = max(15, round(클립수 × 0.5 + 10))`이므로 클립
  1~2개면 15분 → `refund50At = now + 45분`. 8/14 (1) 세션의 Firestore
  실측(16:53:38, 렌더 시작 +45분)과 일치. `refund100At`도 고정 24시간
  실측과 일치.
