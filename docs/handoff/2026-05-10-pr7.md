## 자체 학습

- **CC 출력 잘림 패턴 반복**: 1단·2단 보고 모두 git push 출력이 안 보였음. push 검증을 별도 명령(git log origin/main..HEAD --oneline)으로 두 번 추가 확인. 다음 라운드 프롬프트부터 보고 항목에 "git push 명령 출력 그대로 인용" 명시.

- **CC가 같은 결과 두 번 보낼 수 있음**: 라운드 2 보고를 라운드 3 프롬프트 전달 전에 다시 받음. 다음부터 CC 보고 받으면 "이게 어느 라운드 결과인지" 보고 머리부터 확인.

- **무게 의제 추정치 정확도**: 본 세션 초반 "DECISIONS 40+, known-issues 25+" 추정. 실측 44 / 28. 추정치 ±10% 범위로 합리적이지만, 추정으로 계획 세우면 안 되고 정찰 1라운드에서 실측 카운트 받는 게 정합.

- **마이그레이션 작업의 정찰→결정→실행 분해**: 2단 작업을 라운드 2(분류 정찰) → 본 채팅 검수(영역 추가, 모호 항목 결정) → 라운드 3(실행) → 라운드 4(검증) 4라운드로 분해. 9파일 동시 변경 같은 큰 작업에서 분류 매핑을 본 채팅에서 박아 CC가 다시 분류하지 않게 한 패턴이 사고 회피에 효과.

- **본문 보존 검증**: 마이그레이션에서 "본문 손실 0"을 보장하기 위해 스폿 체크 5개(무작위 항목 본문 첫 줄 grep) 패턴이 정상 작동. 비용 작고 회수 큼.
