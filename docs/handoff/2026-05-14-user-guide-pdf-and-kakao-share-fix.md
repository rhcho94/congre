## Track A — 호스트·게스트 사용 설명서 PDF

### 결정 과정

운영자 요청: 호스트용 + 게스트용 사용 설명서를 만들어 **문서로 배포 + 앱 랜딩 페이지 섹션에 삽입**.
컨텐츠 톤은 소개서(congre-deck.pdf)와 동일 방식 — "화면 캡처 + 해설" 페어.

3단계로 분해:
- 1단계: 페이지 구조표 확정 (호스트 8 + 게스트 6) — 운영자 승인
- 2단계: 본문 작성 (각 페이지별 헤더·제목·본문 블록·이미지 매핑) — 운영자 승인
- 3단계: 두 채널 적용 — PDF는 본 세션 처리, 랜딩 페이지는 다음 세션

### 결과물 (3개 PDF, /mnt/user-data/outputs/)

| 파일 | 페이지 | 크기 |
|---|---|---|
| `congre-host-guide.pdf` | 8 | 832 KB |
| `congre-guest-guide.pdf` | 6 | 648 KB |
| `congre-user-guide.pdf` (합본 표지 + 호스트 + 게스트) | 15 | 1.4 MB |

### 빌드 환경 (재현용 메모)

- reportlab 4.4.10 + Pillow 12.1.1 (사전 설치됨)
- 폰트: Cormorant Garamond Italic/BoldItalic + DM Sans Regular/Medium/Bold + NotoSansKR Regular/Medium/Bold
- 폰트 출처: `@fontsource/*` npm 패키지에서 WOFF 추출 후 fonttools로 TTF 변환 (raw.githubusercontent.com 차단으로 github 직접 다운로드 불가)
- 디자인 토큰: 소개서와 동일 (--bg #0c0b09, --accent #c8892c, --text #ede8df 등)
- 페이지 크기: A4 가로 (842×595)

### 작업 중 발견된 사고 + 학습

**사고 1 — 한글/영문 폰트 자동 전환 누락 (헤더)**

- 헤더 `draw_header` 함수가 `c.setFont("DMSans-Medium")` + `c.drawString`으로 단순 처리
  → 한글 부분이 빈 글리프(null)로 출력
- 본문은 `draw_mixed_text`로 자동 전환 처리되어 OK
- 패치: 헤더와 `draw_section_tag`도 `draw_mixed_text` 사용으로 통일

**사고 2 — NotoKR·DMSans 모두 글리프 없는 특수 기호 (→ ▶ ↻)**

- WOFF에서 추출한 한글 서브셋이 좁아 화살표·재생 기호 등 미포함
- 해결: 본문에서 기호 제거 → 텍스트로 대체 ("→ 등록된" → "후 등록된", "▶ 버튼" → "재생 버튼" 등)
- 부수 효과로 톤이 더 친근해짐

**사고 3 — 21장 이미지 매핑 추정 오류 (가장 큰 사고)**

- 카톡 첨부 순서로 본 인덱스(#1차-N, #2차-N)와 파일명 번호가 일치한다고 단정
- 21장 모두 직접 view로 확인하지 않고 추정으로 매핑 → 페이지마다 그림이 본문과 안 맞음
- 운영자 한 질문("파일 어디 있어?") 후 시각 검증하다 발견
- 정정: 21장 격자 이미지 만들어 한 번에 확인 → 정확한 매핑 표 작성 → 재빌드
- **학습 한 줄**: 화면 본 순서(인지된 순서)와 파일명 번호가 일치한다고 단정하지 말 것. 화면 매핑은 추정 말고 직접 view로.

**사고 4 — 보수적 옵션 추천이 1차 변화 부족 (이전 세션에서 이어진 패턴)**

- 이번 세션엔 시각 영역 옵션 카드 없었으나, 이전 세션 학습("보수→중간→과감 3단계 중 중간 추천")이 결정 톤에 반영됨

## Track B — 카카오 공유 fallback 사고 (regression of d74152e)

### 버그 정의 (정정 과정 포함)

**초기 보고**: "카카오톡 공유하기 누르면 Congre 초기화면으로 가, 링크 복사는 정상"

채팅 클로드 1차 가설: 공유 버튼 클릭 즉시 호스트 페이지에서 홈으로 이동 (가설 A·B·C)

**운영자 정정**: 공유 버튼 클릭 자체는 정상, 카톡 메시지 전송도 정상. **공유받은 사람이 카톡의 링크를 탭하면** 호스트 완성본이 아니라 Congre 홈(랜딩)의 샘플 영상 스크롤 위치로 떨어짐.

→ 추측 깨짐 정정: "초기화면으로 가"를 "발신자 페이지에서 홈으로 즉시 이동"으로 단정한 게 원인. 발신자 페이지의 동작이 아니라 수신자가 받은 URL의 동작이 진짜 문제.

### 진단 결과 (CC 정찰 2회)

**원인**: 카카오 공유의 `link.webUrl`이 `cdn.shotstack.io` URL인데, 이 도메인이 카카오 개발자 콘솔 미등록 도메인이라 카카오가 fallback(홈)으로 처리.

**커밋 이력으로 확인된 regression**:
- d74152e (2026-05-09): `/share/{eventId}` 페이지 신설 + 카톡 공유 링크를 거기로 변경. 커밋 메시지에 **"cdn.shotstack.io는 카카오 콘솔 미등록 도메인 fallback 사고 해소"** 명시
- 09a6d9a (2026-05-12): "초대장 기능 전체 제거" 결정으로 `/share` 페이지 제거, 카카오 공유 링크를 `event.videoUrl`로 되돌림. **카카오 도메인 제약은 결정 본문에 누락**
- 5/14 (본 세션): 재도입

### 해결 작업

**작업 1**: d74152e 시점 파일 그대로 복원 (`git show d74152e:` 사용)
- `src/app/share/[eventId]/page.tsx` (SSR + OG 메타 태그)
- `src/app/share/[eventId]/ShareActions.tsx` (클라이언트 컴포넌트)

호환성 점검: getAdminDb, BrandName withMadeBy 등 모두 현재 코드베이스와 호환 (변경 없음 확인)

**작업 2**: dashboard 카카오 공유 핸들러 수정
- `src/app/dashboard/events/[eventId]/page.tsx` `handleKakaoShare`
- `link.mobileWebUrl / webUrl`을 `event.videoUrl` → `${appUrl}/share/${eventId}`
- 빈 appUrl 가드 + console.warn fallback 추가

**작업 3**: `.env.local.example`에 `NEXT_PUBLIC_APP_URL` 항목 추가 (단, `.gitignore` 36번째 줄 `.env*` 패턴으로 커밋 제외됨 — 보정 후보로 기록)

**작업 4**: DECISIONS + CHANGELOG 갱신 — **5/12 결정문에 누락됐던 "카카오 콘솔 미등록 도메인 fallback" 기술 제약을 5/14 결정문에 명시**

### Track B 학습 한 줄

> 결정 본문에 "왜 이 방식을 선택했나"만 적고 "이전 방식을 만들었던 이유"를 누락하면 같은 사고가 재발한다.

5/12 결정문에 "영상 직링크가 더 직관적"은 있었지만 d74152e 시점에 만든 이유(카카오 도메인 제약)는 빠짐.
→ 결정 시 **이전 방식을 폐기할 때 그 방식이 해결했던 문제가 무엇이었는지 함께 기록** 필요.

### 추가 발견 — Vercel 환경변수 Sensitive UX 이슈

- 기존 `NEXT_PUBLIC_APP_URL` 항목이 Sensitive 활성화되어 있었고, 값이 잘못 들어가 있었음 (잘못된 값 정체 미확인)
- Sensitive 켜져 있으면 값 확인·수정이 까다로움
- `NEXT_PUBLIC_*` 변수는 어차피 클라이언트 번들에 포함되어 누구나 볼 수 있으므로 Sensitive 옵션 의미 없음
- 운영자 처리: 항목 삭제 → 새로 추가 (Sensitive 해제, 3환경 체크) → Redeploy (Build Cache 해제)
- **다음에 같은 패턴 만나면 같은 절차로 처리** (한 줄 메모로 남김)
