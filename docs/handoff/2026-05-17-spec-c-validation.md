### 정찰 — 첨부 자료 확인

| 자료 | 상태 |

### 본인 1차 정찰 결과

`shotstack.ts` 본문에서 회수:

- `createRender(clips: Array<{ src: string; length: number }>, ...)` 시그니처 — length는 호출자 영역
- `videoClips` 매핑: `length: clip.length` 그대로. **`shotstack.ts` 자체에 길이 결정 로직 없음**
- `length: "auto"` 키워드가 본 파일 내 다른 클립에서 이미 사용 중 (intro/outro 영상)
- `trim: 0` 명시 — Shotstack에 trim 파라미터 존재 증거

호출자(`createRender` 사용처) 본문 본 적 없음. 사양 C 본문 어디까지 결정됐는지 본 적 없음.

### 운영자에 사양 본문 요청 단계 — 사고 #1 발생 시점

본인이 사양 C가 무엇을 가리키는지 본문 없어 단정 불가. 운영자에 본문 요청.

운영자 응답: "OS 네이티브 카메라 이전 후 영상 길이를 앱에서 조절할 수 없게 됨. 호스트 30초 상한 강제 + 게스트 임의 길이 freeze/검은 화면 방지 영역" 골격 재구성.

**본인 처리**: 사양 미결정 가정 하에 광범위 정찰 진입. 옵션 카드 작성 단계로 진행.

**사고 #1 차단 실패 지점**: 운영자에 본문 요청과 **동시에 CC 정찰을 띄우지 않음**. 직렬(운영자 답변 → 그 위에서 옵션 카드 작성) 흐름이 운영자 misremember 사고 차단 못 함. 본 시점이 가장 일찍 차단할 수 있었던 영역.

## Track B — 광범위 정찰 (사고 #2 누적 + 정찰 자료 부산물)

### 정찰 4축 (Shotstack · 클라이언트 · 서버 · 외부 SaaS)

운영자 "광범위하게 조사" 트리거로 4개 축 모두 정찰:

| 축 | 핵심 사실 |
|---|---|
| Shotstack 자체 | `length: "auto"` (video asset) 존재 / `trim` 필드 존재 / length를 영상 실제 길이보다 길게 명시 시 freeze 동작 |
| 클라이언트 측 | `<video>` element + `loadedmetadata` 약 10줄. iOS/Android 네이티브 카메라 MP4는 duration 메타데이터 정상 (MediaRecorder webm 사고 무관) |
| 서버 측 (Vercel) | ffprobe 가능하나 Vercel staff 권고 외 (50MB 한도, "we generally do not recommend") |
| 외부 SaaS | Shotstack probe API / ffmpeg-api.com 등 존재. 본 문제에 과함 |

### 옵션 카드 4개 작성 → 운영자 옵션 2 선택

| 옵션 | 골격 | 운영자 선택 |
|---|---|---|
| 1 | Shotstack `length: "auto"`만 사용 | 후순위 |
| **2** | **클라이언트 측 측정 + Firestore 저장 + `Math.min(duration, 호스트상한)` length 전달** | **채택** |
| 3 | 클라이언트에서 미리 거절 (보수적) | 게스트 UX 부담 |
| 4 | 서버 측 ffprobe | Vercel 권고 외 |

### 사고 #2 발생 지점 — Freeze 시나리오 단정

Shotstack 문서 회수 단계에서 본인 발화:

> "= 가설이 사실로 확인됨. 30초 슬롯에 21초 영상이 들어가면 마지막 9초는 마지막 프레임 freeze. 검은 화면이 아니라 freeze. 운영자 추정 절반 적중 (freeze ○, black ×)."

실제 문서 문장은 **"If you extend the duration of a clip longer than the actual duration"** — 개발자가 length를 잘못 명시했을 때만 발생. 본 프로젝트는 `Math.min` 계산으로 length를 실제 길이 이하로 제한 → freeze 시나리오 자체 무관.

**본인 사고**: 문서 문장과 운영자 가설을 동일 시나리오로 단정. 두 시나리오의 입력 조건(length 값 결정 방식) 다른 것 무시.

**검출**: 운영자가 "실제 완성된 결과물에서 이렇게 된다는 건 아니지? 짧은 동영상은 그냥 그 길이대로 재생되는거지?" 한 마디로 즉시 잡음.

**CLAUDE.md 룰 적용 실패**: 본 사고는 직전 세션 등재 룰 "단편 단서로 전체 단정 금지"(f68b4c0)의 적용 실패 사례. 룰이 본인 의식에 작동했다면 차단됐어야 함. 본인용 메모.

## 본 세션 학습

### 1. 사고 #1 — 운영자 기억 의존 신호 직렬 처리

운영자가 본 세션 초반 "내 기억에 의존해서 너에게 말한다는 상황 자체가 위험" 신호 직접 전달. 본인이 그 신호를 일반 진단(누수 4지점 분석)으로 처리하고 다음 진행 시(사양 본문 요청 단계) 그 신호를 다시 떠올리지 못함. **신호 인지와 실제 적용 사이에 시차**.

학습이 외화(룰 등재)되어야 다음 세션에 작동. 본 세션 Kickoff 룰 5번 등재로 외화 완료.

### 2. 사고 #2 — 룰 적용 실패 사례

직전 세션 등재 룰 "단편 단서로 전체 단정 금지"(f68b4c0)의 적용 실패. 룰을 본인이 의식하고 있었다면 차단됐어야 함. 다만 본 세션 등재된 다른 룰("운영자 기억 의존 신호" = 5번)이 작동했다면 사고 #1이 차단됐고 사고 #2가 발생할 흐름 자체가 없었음. 두 사고가 인과 연결.

### 3. 검증 표 룰 두 영역에서 사고 발견 효과

- CC 정찰 보고 직후 검증 표로 옵션 카드 무용 즉시 직시
- 등재 작업 보고 검증 표에서 CHANGELOG 헤더 사고 의외값 1건 포착

검증 표 룰 본 세션도 효과 입증.

### 4. 학습 발화와 실제 적용 사이 1답변 시차

본인이 사고 #1 학습을 직전 답변에 1줄 적은 직후 답변에서 사고 #2 발생. **답변 내 자기 학습 발화만으론 다음 답변 적용 보장 안 됨**. 핸드오프 또는 룰 등재로 외화되어야 작동. 본 세션도 같은 패턴 입증.

### 5. 운영자 책임 분담

운영자가 사양 C 본문 재구성한 것은 비개발자 1인이 7개월 프로젝트를 머리에 담고 있는 환경에서 자연스러운 협조. 망각·misremember 자체는 운영자 책임 영역 아님. 운영자가 본 세션 초반 "기억 의존 위험" 신호 직접 줬는데 본인이 CC 정찰을 같이 띄우지 않은 게 본인 책임. 자책 영역 아닌 책임 분담 명확화.

- Shotstack `length: "auto"` (video asset) 동작 확인 — 영상 실제 길이로 자동 설정
- Shotstack freeze 동작 정정 — `length`를 실제 길이보다 길게 명시 시에만 발생. 현재 코드 `Math.min(duration, maxClipSeconds)`는 본 시나리오에 노출 안 됨 (본 세션 사고 #2 정정 흔적)
- Shotstack `trim` 필드 — 영상 앞부분 자르기
- 클라이언트 측 duration 측정 패턴 — `<video>` + `loadedmetadata` 약 10줄
- Vercel + ffmpeg 부적합 — 50MB serverless 한도, Vercel staff 권고 외
- iOS/Android 네이티브 카메라 MP4 — duration 메타데이터 정상
