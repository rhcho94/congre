## 이번 세션 종료 — 베타 쿠폰 해제 트랙
- **목적**: Toss 심사 대기 중 결제 없이 실베타 이벤트 운영
- **방식**: 화이트리스트 전화번호(Firestore `betaCoupons` 컬렉션, 문서 ID = 정규화 전화번호) 입력 시 paid 플랜 임시 해제. 운영자가 콘솔에서 번호 수동 관리.
- **커밋**: `b0e7988` (push·Vercel 배포 완료), 파일 4개
  - `src/app/api/events/route.ts`: 쿠폰 경로 = 서버 전권. 유효 쿠폰이면 클라 body의 plan/maxClips/maxClipSeconds를 무시하고 `plan:"paid"·unlocked:true·unlockedBy:번호·maxClips:20·maxClipSeconds:30` 고정 저장. 이벤트 생성 성공 후 쿠폰에 `used:true`+`eventId` 기록(소진). 쿠폰 없음→`INVALID_COUPON`, used→`COUPON_ALREADY_USED`. 소진은 단순 확인→쓰기(트랜잭션 아님, Ray 결정). 전화번호 정규화는 서버 `replace(/\D/g,"")`.
  - `src/app/api/render/start/route.ts`: 렌더 게이트를 `plan==="paid"` 무조건 차단 → `plan==="paid" && !unlocked` 로 교체. `unlocked===true`면 통과. **결제 붙을 때 재사용 경로**(결제 성공도 같은 unlocked 필드를 켜는 방식). free 이벤트 무영향.
  - `src/app/dashboard/create/page.tsx`: 쿠폰 입력 시 plan 라디오·paid 스테퍼 렌더 제외, "20개×30초 고정" 안내 노출.
  - `src/lib/events.ts`: `unlocked?`/`unlockedBy?` optional 타입 추가.
- **실전 검증 5종 전부 통과**:
  1. 쿠폰 등록 (`betaCoupons/01075822020`)
  2. 그 번호로 이벤트 생성 (이벤트 `5iMsfLpsPOc73nBsEyaD`)
  3. 저장값 5개 확인 — `plan:"paid"`, `unlocked:true`, `unlockedBy:"01075822020"`, `maxClips:20`, `maxClipSeconds:30`
  4. 재사용 거부 — 같은 번호 재시도 시 생성 차단, 쿠폰 문서 `used:true` 소진 확인 (인과 확정)
  5. 클립 업로드 + 렌더 — Shotstack까지 실통과 (게이트 해제 실전 작동)
- **임시 기능 철수법**: 결제 붙으면 ①생성 화면 쿠폰 입력란 제거 ②`betaCoupons` 컬렉션 비우기. 렌더 게이트는 결제가 승계하므로 손대지 않음.

## 다음 세션 트랙 — 게스트 화면 UI (정찰부터)
아직 코드 미확인 영역. 착수 시 정찰(업로드 페이지 + 이름·전번 입력 화면 + 생성 화면 문자열/스타일) 먼저. 화면 추정만으로 실행 프롬프트 금지.

1. **"고길동" 사전 입력값 잔존** (Ray 지목 핵심) — 지워졌어야 할 하드코딩 기본값이 실데이터(호스트 입력값)와 겹쳐 표시됨. 업로드 화면 설명이 "고길동님과 함께 만드는 조래환씨의 축하영상입니다 영상입니다" 식으로 디폴트+입력값 중복. 정찰: 이 사전값이 어느 파일·어느 변수에서 오는지.
2. **배경 위 검은 글자 대비 불량** — 업로드 화면 설명 텍스트가 배경 사진에 묻혀 안 보임. CSS 대비 문제(밝은 색 또는 오버레이 부재).
3. **뭉뚱그린 에러 문구** — 쿠폰 재사용 거부 시 서버는 `COUPON_ALREADY_USED`를 반환하나 프론트가 "이벤트 생성 중 오류가 발생했습니다. 다시 시도해주세요."로 뭉갬. 실원인이 안 보여 사용자가 무한 재시도할 수 있음. (생성 화면 코드, 1·2와 별개 파일일 수 있음)
4. **[문구 추가, 버그 아님] 게스트 초대장 이름 입력란 위 안내 추가** — "닉네임 아무거나 입력해도 됩니다." 성격상 버그 수정이 아닌 신규 문구. 정찰 시 **이름·전번 입력 화면이 업로드 페이지와 동일 파일인지 별개인지**부터 확인 필요.
