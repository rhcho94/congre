## FAQ 답변의 근거값 — 코드·약관 실측

FAQ는 공개 고지 문서라 약관과 어긋나면 심사 리스크가 된다. 답변에
쓴 값은 전부 아래에서 뽑았다. 문서 기억으로 채운 값은 없다.

| 항목 | 값 | 출처 |
|---|---|---|
| 결제 시점 | 마감 시점, 완료 즉시 제작 개시 | `terms/page.tsx:170` |
| 최소 금액 | 10,000원 | `lib/plans.ts:21` MIN_PRICE |
| 유료 클립 수 | 10~200개 서버 강제 | `api/events/route.ts:89-90` |
| 클립 길이 | 무료 10초 / 유료 10~100초, 5초 배수 | `plans.ts:12-15`, `events:102-104` |
| 무료 플랜 | 5클립·10초·워터마크·다운로드 가능 | `plans.ts:4,13` |
| 환불 | 4h 이내 없음 / 4~48h 50% / 48h 초과 100% | `terms:183-185` |
| 클립 보관 | 참가자 결과 알림 발송 + 약 48시간 | `terms:208` |
| 완성본 보관 | 생성 시점 + 7일 | `terms:209` |
| 삭제 오차 | 1일 1회 배치, 최대 약 24시간 | `terms:211` |
| 재편집 창 | 클립이 보존된 기간 내에서만 | `terms` 제14조 ④ |

**정밀도 메모**: known-issues는 재편집 창을 "완성본 출력 후 48시간"으로
적었으나 실제 기산점은 **참가자 결과 알림 발송 시점**이다
(`terms:208` + `participantNotifiedAt`). FAQ에는 정확한 쪽으로 썼다.

**금액 상한**: 별도 상수는 없다. 100초 × 200개 × 100원 = 2,000,000원은
두 가드의 곱으로 도출되는 값이고 코드에 명시된 상수가 아니다.
토스 1차 회신의 최고가 확약 200만원과 일치한다.

**용어**: 같은 기능을 약관 "재렌더" / 랜딩 "재편집" / 앱 UI "다시 만들기"로
부르는 known-issue가 있다. FAQ는 고객 대상이라 랜딩과 같은 **"재편집"**으로
통일했다. 네 번째 표기를 만들지 않았다.

`npx vercel --prod --yes`가 `Not authorized`로 실패했다.
`.vercel/project.json`이 5월 26일자였고 그 사이 계정 구성이 바뀐 것이

**복구 과정에서 사고 1건**: `npx vercel link --yes`를 실행해
`--yes`가 질문을 건너뛰고 **폴더 이름으로 새 프로젝트 `deploy`를
생성**했다. `congre.kr`에는 영향 없었고(엉뚱한 URL로 배포됨),
`.vercel` + `.env.local` 삭제 후 `npx vercel link`(`--yes` 없이)
→ `Search all projects` → `congre-landing` 선택으로 복구했다.
오생성된 `deploy` 프로젝트는 Vercel 웹에서 삭제 완료.

**진단 정정**: 실패 원인을 "`orgId`가 접근 불가 팀 스코프를 가리킨다"로
짚었으나 틀렸다. 재연결 후에도 `orgId`는 동일한
`team_Xb4u7wtSBe95wmkBxKZx3eVF`이고 그대로 배포가 성공했다.
`rhcho94s-projects`는 개인 계정이지만 Vercel 내부에서 `team_` 접두사
ID를 갖는다 — 정상이다. 실제 원인은 `projectId` 또는 토큰 쪽이었을
가능성이 크나 확정하지 못했다.
