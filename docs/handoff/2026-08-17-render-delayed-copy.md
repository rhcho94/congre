## 문제의 구조 — 두 시계의 기산점이 달랐다

문구는 "지금으로부터 30분"이라는 **상대시간**을 말했으나, 실제 환불선은
**절대시각**이었다.

- 지연 알림 발송 시점 = `renderStartedAt` + `renderEstimateMin`
  (`render/start/route.ts:197`, 하한 15분, **상한 캡 없음**, 클립 1개당 +0.5분)
- `refund50At` = `paidAt` + 4시간 고정 (`payment/confirm/route.ts:118-132`)

기산점이 서로 다르고 한쪽이 가변이라, 어떤 고정 숫자를 넣어도 클립 수에 따라
계속 어긋난다. 그래서 **상대시간 표현 자체를 버리고 기산점을 문구에 명시**하는
방식을 택했다. 리터럴이지만 `paidAt` 기준 고정 상수라 항상 정확하다.

동적 치환(`refund50At` 절대시각 표시)은 검토했으나 채택하지 않았다. 알림
컨텍스트에 `refund50At` 배선 + KST 포맷팅 + SMS 바이트 압박이 붙어 범위가
커진다. 실고객 문의가 실제로 발생하면 그때 격상한다(YAGNI).

## SMS 90바이트 — 신규 등재 (known-issues)

UTF-8 실측 고정부(`{title}` 제외):

| | 고정부 | 90B 여유 |
|---|---|---|
| 원본("30분 후") | 88B | +2B |
| 초안("결제 후 4시간 경과 시") | 108B | −18B |
| 확정("결제 4시간 후") | **97B** | **−7B** |

**이번 커밋이 만든 문제가 아니다.** 원본 88B도 `{title}`이 한 글자만 들어가면
초과였다. 즉 `sms-templates.ts:8-9`의 90B 제약은 **처음부터 지켜진 적이 없다.**
확정안은 초안 대비 11B를 회수했으나 90B 달성에는 이르지 못했다.

- SOLAPI가 SMS→LMS 자동 승급하므로 발송 자체는 된다(`:9` 주석). 강제 검증 없음.
- 90B를 실제로 맞추려면 "문의: 카카오톡 @congre"(UTF-8 28B) 제거 수준의
  문안 재설계가 필요해 범위 밖으로 뒀다.
- **같은 파일의 다른 템플릿은 실측하지 않았다.** 동일 초과 가능성 있으나 미확인.
- `:8-9` 주석은 **고치지 않았다.** 목표를 적은 주석이라 실태에 맞춰 낮추면
  목표가 사라진다.

## 이번 세션 학습

- **바이트 수는 인코딩부터 확인한다.** 채팅 클로드가 "한국 SMS는 EUC-KR
  2바이트"라는 통념으로 76B/85B를 계산했으나 실측은 UTF-8 3바이트 기준
  88B/108B였다. 전제가 틀려 "변경 전과 같은 여유를 유지한다"는 추천 근거가
  무너졌다(결론은 유지됐다 — 초과분이 18B→7B로 줄었으므로). API 용어
  이름값 추론 사고와 같은 계열: **단위·인코딩·기준을 확인하지 않고 통념으로
  전제를 세우는 것.**

- **"N곳"에 단위를 붙이지 않으면 문서에 그대로 박힌다.** 프롬프트에 "문구
  4곳"이라 썼으나 실제는 문구 3곳 + 주석 1곳 = 파일 4개였다. CC가 커밋 전에
  짚어 잡혔다. 숫자를 프롬프트에 쓸 때 무엇의 개수인지 명시할 것.

- **미커밋 누적 diff 조건을 이번엔 미리 걸었다.** SMS 재편집 턴에서 실제
  변경은 1파일 1줄이지만 diff는 4파일로 나오는 상황이었고, 검증 조건을 턴
  범위가 아니라 **누적 예상치(4파일 4↑/4↓)**로 걸어 오탐이 나지 않았다.
  지난 세션에 두 번 오탐이 났던 자리다. 룰이 절차에 반영된 첫 사례.

- **CC 인용 축약이 파일 손상으로 오인될 수 있다.** docs 작업 보고에서
  인용문 여러 곳이 중간에 끊겨 파일 손상 가능성을 의심했으나, 직접 읽은
  결과 파일은 온전했고 CC가 인용을 줄인 것이었다. 학습 룰(터미널 출력
  잘림 ≠ 파일 손상)대로 직접 읽기로 확정한 것이 맞았다. **다만 이번엔
  하필 실제 문서 제목·본문이 끊긴 자리라 확인 없이 넘기지 않은 것도 맞다.**

- **axe가 보고 규칙을 어겼다.** "변경 전/후 원문 인용"을 명시했으나 서술로만
  보고해 CC 본체가 직접 diff를 뽑아 보완했다. 작업 자체는 사양대로였다.

  실제로 읽고 인용할 것, 안 읽었으면 확인 못 함으로"를 그대로 전달한 결과다.
  지난 세션 2회 반복됐던 CLAUDE.md baseline 허위 기재가 재발하지 않았다.
